# برند پویا از پنل ادمین محصول (نام، لوگو، آیکون، رنگ، متن) — بدون سورس

> **خواسته‌ی اصلی:** «در پنل مدیر یک فیلدِ تنظیم برند وجود داشته باشد تا با آن، برند پلتفرم
> به‌دلخواه تنظیم شود؛ آیکون و لوگوی پلتفرم هم به‌صورت بارگذاری فایل تصویر انجام شود.»

این سند راهی را شرح می‌دهد که **بدون سورس فروشنده** آن را کامل پیاده می‌کند:
پنل ادمین محصول (`/dash`) یک دکمه‌ی «⚙️ تنظیمات برند» می‌گیرد؛ ادمین (نقش ۱) نام/توضیح/رنگ را
ویرایش و **لوگو و آیکون را فایل آپلود** می‌کند؛ تغییرات فوراً برای همه‌ی کاربران اعمال می‌شود.

---

## ۱) معماری — چرا این‌طور کار می‌کند

باینری PersianMeet متن‌باز نیست و تغییر کد آن ممکن نیست؛ ولی دو واقعیت تست‌شده این مسیر را ممکن می‌کند:

1. **فرانت‌اند `dist/` از دیسک سرو می‌شود، نه از حافظه.** هر فایلی که *بعد از* بیلد به `dist/`
   اضافه شود، بلافاصله با HTTP 200 قابل آدرس‌دهی است (آزمایش زنده روی نسخه‌ی ۰٫۲۶٫۳ انجام شد).
2. دیکشنری i18n محصول در `dist/translate.js` یک شیء گلوبال `window.translate` است و بلافاصله
   قبل از Vue لود می‌شود — یعنی می‌توان آن را در لحظه وصله کرد.

پس کل سازوکار در دو لایه است:

```
┌─ dist محصول (فقط همین دو فایل به آن اضافه می‌شود) ─────────────┐
│  brand/brand-bridge.js   ← پل برند: i18n را وصله می‌کند، title/meta/favicon را         │
│                             عوض می‌کند، متن‌های صفحه را با نام برند جایگزین می‌کند،       │
│                             منیفست PWA پویا می‌سازد، و دکمه/مودال «⚙️ تنظیمات برند»      │
│                             را برای ادمین در /dash نشان می‌دهد                          │
│  brand/brand.json        ← پیکربندی برند (siteName, tagline, primaryColor, …)          │
│  brand/logo.png          ← لوگوی آپلودی      brand/icon.png ← آیکون آپلودی              │
└──────────────────────────────────────────────────────────────────┘
            ▲ خواندن عمومی (no-store)         ▲ نوشتن (فقط ادمین، احراز با GUID محصول)
            │                                   │
   کاربران همه‌ی صفحات              ┌───────────┴────────────┐
                                     │ classroom-manager      │  127.0.0.1:8090
                                     │  POST /brand-api/save  │  multipart: فیلدها + logo/icon
                                     │  GET  /brand-api/...   │
                                     └────────────────────────┘
                                                   ▲
                          nginx هم‌مبدأ:  location /brand-api/  →  127.0.0.1:8090
                                          location /brand/      →  127.0.0.1:8003 (no-store)
```

**احراز هویت ذخیره:** پل، `GUID` ادمین را از `localStorage["user"]` می‌خواند و در هدر
`X-PM-GUID` می‌فرستد. classroom-manager این GUID را با **خودِ محصول** اعتبارسنجی می‌کند
(`POST /api {Type:"panelUserList", Secret:"<GUID>"}`): اگر پاسخ `{"Status":"ok"}` بود یعنی
هدایت‌کننده ادمینِ محصول است؛ در غیر این صورت `403`. هیچ رمز یا secret مشترکی بین دو سرویس
ردوبدل نمی‌شود و توکن کاربران عادی هم کار نمی‌کند (تست شد: GUID کاربر عادی → `403`).

## ۲) نصب

### روی نصب‌های جدید (داخل install.sh)

`deploy/install.sh` به‌صورت پیش‌فرض بعد از نصب، `branding/install-brand.py` را اجرا می‌کند
(غیرفعال‌سازی: `WITH_BRAND=0`). متغیرهای اختیاری: `BRAND_SITE_NAME`، `BRAND_TAGLINE`، `BRAND_PRIMARY_COLOR`.

### روی نصب‌های موجود

```bash
cd /opt/bacirat-function          # یا هر جا ریپو را کلون کرده‌اید
sudo python3 branding/install-brand.py --dist /opt/persianmeet/dist \
     --site-name "مدرسه ما" --tagline "آموزش آنلاین" --primary-color "#0ea5e9"
```

کارهایی که می‌کند (همه idempotent و با backup خودکار `index.html`):

1. `dist/brand/brand-bridge.js` و پیش‌فرض `dist/brand/brand.json` را می‌سازد؛
2. یک `<script src="/brand/brand-bridge.js">` بلافاصله بعد از `/translate.js` در `<head>`
   تزریق می‌کند (این *تنها* ویرایش یک فایل فروشنده است)؛
3. بلاک ریدایرکت فروشنده به `app2.learn100.ir` را حذف می‌کند
   (`--keep-learn100-redirect` برای نگه‌داشتنش).

بعد از نصب: `sudo systemctl reload nginx && sudo systemctl restart persianmeet classroom-manager`
(در عمل reload لازم نیست — dist از دیسک خوانده می‌شود — ولی بی‌ضرر است).

### تنظیمات nginx (ضروری برای کش و پروکسی)

در `deploy/nginx.reverse-proxy.conf` اضافه شده و باید در کانفیگ سرورتان باشد:

```nginx
location /brand/     { proxy_pass http://127.0.0.1:8003; add_header Cache-Control "no-store" always; }
location /brand-api/ { proxy_pass http://127.0.0.1:8090; client_max_body_size 5m; … }
```

اگر از nginx استفاده نمی‌کنید (دسترسی مستقیم روی پورت ۸۰۰۳): `/brand-api/` در دسترس نخواهد بود
(ذخیره از پنل کار نمی‌کند)؛ خواندن `/brand/brand.json` کار می‌کند ولی ممکن است توسط مرورگر کش شود.
پیشنهاد اکید: nginx جلوی سرویس + همین دو location.

## ۳) استفاده از «تنظیمات برند» در پنل ادمین محصول

1. با **حساب ادمین محصول** (نقش ۱) وارد شوید و به **`/dash`** بروید (همان پنل مدیریت فروشنده).
2. دکمه‌ی شناور «⚙️ تنظیمات برند» گوشه‌ی پایین-چپ ظاهر می‌شود.
3. فیلدها:
   - **نام پلتفرم** (اجباری) — همه‌جا جایگزین «پرشین میت»/«PersianMeet»/… می‌شود: عنوان تب مرورگر،
     واژه‌نامه‌های i18n، متن صفحه‌ها، منیفست PWA.
   - **نام کوتاه** — برای آیکون اپ روی موبایل.
   - **توضیح کوتاه / تگ‌لاین** — `<meta description>` و زیرعنوان خوش‌آمد.
   - **رنگ اصلی** — `theme-color`، منیفست PWA و متغیرهای CSS رنگ اصلی PrimeVue.
   - **لوگو** — فایل تصویر (PNG/JPEG/GIF/WEBP/SVG، حداکثر ۲MB)؛ در `<img>`‌های لوگوی صفحه جایگزین می‌شود.
   - **آیکون** — فایل تصویر مربعی؛ favicon و apple-touch-icon و PWA icon را عوض می‌کند.
4. «ذخیره برند» → نوشتن اتمیک در `dist/brand/` → صفحه خودکار رفرش می‌شود؛ **برای همه‌ی کاربران** اعمال می‌شود.

> لوگو/آیکون با **نام ثابت** (`logo.png`/`icon.png`) و کوئریِ `?v=<unix-ts>` ذخیره می‌شوند تا کش مرورگر دور زده شود.

## ۴) چه چیزهایی «به‌دلخواه» تغییر می‌کند و چه چیزهایی نه

| مورد | وضعیت |
|---|---|
| نام پلتفرم در همه‌ی متن‌ها (fa/en/ar/hi/az/zh/fr/de/…) | ✅ جایگزین در دیکشنری i18n + متن‌های DOM |
| عنوان تب مرورگر / `theme-color` / توضیح صفحه | ✅ |
| favicon و apple-touch-icon | ✅ با آپلود آیکون |
| نصب PWA (نام و آیکون اپ) | ✅ منیفست پویا (blob) — برای نصب‌های بعدی |
| رنگ اصلی (دکمه‌های اکسنت/تم) | ✅ از طریق CSS variables رایج + theme-color (شدت تغییر بسته به قالب محصول است) |
| لوگوی درون تصاویر ثابت برند (pngهای داخل assets) | ⚠️ اگر جایی از `<img src="…logo…">` استفاده شده باشد جایگزین می‌شود؛ تصاویر با هشِ بیلد که نام برند درشان نباشد، خیر |
| فونت فارسی اختصاصی | ❌ در نسخه‌ی فعلی پل پشتیبانی نشد (Vazir فروشنده باقی می‌ماند) |
| متن‌های کاملاً بازاریابی درون bundle های minified با literal سفارشی | ⚠️ با MutationObserver متن‌هایی که دقیقاً یکی از رشته‌های برند باشند جایگزین می‌شوند؛ هر رشته‌ی دیگری که خودتان بخواهید اضافه کنید را در `LITERALS` در `brand-bridge.js` اضافه کنید |
| تغییر منطق/گرافیک داخلی فراتر از این موارد | نیازمند سورس فروشنده است |

## ۵) امنیت

- `POST /brand-api/save` فقط با GUID **ادمین محصول** کار می‌کند (اعتبارسنجی سمت سرور علیه خود محصول).
- آپلود: حداکثر ۲MB، بررسی magic-byte واقعی تصویر (PNG/JPEG/GIF/WEBP/SVG)، ردِ فایل متنی-با-پسوند-عکس.
- نام فایل نهایی ثابت است (`logo.png`/`icon.png`) — مسیر Traversal ممکن نیست.
- بعد از `DeleteMeet` و حذف اتاق، فایل‌های برند کاملاً مستقل‌اند و دست‌نخورده می‌مانند.
- **هشدار باقی‌مانده از سازنده:** کاربر seed شده‌ی `admin/1111` با رمز **Plaintext در دیتابیس** ذخیره شده است
  (کاربران ساخته‌شده از پنل با bcrypt هش می‌شوند). حتماً فوراً رمزش را از پنل عوض کنید و دسترسی به
  `/opt/persianmeet/test.db` را محدود نگه دارید. پسورد لاگ‌های محصول (`journalctl -u persianmeet`) را هم
  فقط برای ادمین‌ها قابل مشاهده بگذارید چون ورودها را لاگ می‌کند.
- Endpoint باز «ثبت‌نام» محصول (`Register`) یوزر نقش ۰ می‌سازد؛ اگر لازم نیست، با فایروال/ریورس‌پراکسی
  به `POST /api` با `Type: Register` را محدود کنید (یا حداقل مانیتور کنید).

## ۶) عیب‌یابی سریع

| علامت | علت محتمل | راه‌حل |
|---|---|---|
| دکمه‌ی ⚙️ دیده نمی‌شود | در `/dash` نیستید یا با حساب غیر ادمین وارد شده‌اید | با ادمین محصول وارد شوید؛ `localStorage["user"].Role` باید `1` باشد |
| ذخیره `403` می‌دهد | GUID شما ادمین نیست یا classroom-manager درست پروکسی نشده | `nginx -t`؛ `curl -s localhost:8090/brand-api/admin-check -H "X-PM-GUID: <guid>"` |
| ذخیره `502/اتصال رد شد` | `proxy_pass /brand-api/` به ۰٫۰٫۰٫۰/پورت اشتباه یا سرویس پایین | `systemctl status classroom-manager`؛ `journalctl -u classroom-manager -f` |
| نام جدید بعد از ذخیره دیده نمی‌شود | کش مرورگر/CDN | فایل‌ها `no-store` هستند؛ hard refresh کنید (Ctrl+Shift+R) |
| آپلود SVG رد می‌شود | SVG شما `<svg` در ابتدا ندارد (مثلاً فقط XML declaration ساده) | فایل را در ادیتور باز و دوباره export کنید |

## ۷) حذف کامل برند و بازگشت به پیش‌فرض

```bash
sudo rm -f /opt/persianmeet/dist/brand/logo.png /opt/persianmeet/dist/brand/icon.png
echo '{"version":1,"siteName":"PersianMeet","siteNameShort":"PersianMeet","tagline":"","primaryColor":"#000000","hasLogo":false,"hasIcon":false}' \
  | sudo tee /opt/persianmeet/dist/brand/brand.json
# برای حذف کامل پل: اسکریپت تزریق‌شده را از index.html بردارید (backup در *.pmbrand-*.bak کنارش هست)
```
