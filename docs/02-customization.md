# سفارشی‌سازی PersianMeet — چه چیزی، کجا، چطور

> این سند پاسخ «من می‌خواهم سورس را تغییر دهم» است؛ صادقانه و لایه‌به‌لایه.
> قاعده‌ی کلی: **هرچیزی که محصول خودش "قابل پیکربندی" کرده را راحت تغییر دهید؛
> هرچیزی که نیست، با روکش بیرونی (reverse proxy) شخصی‌سازی کنید؛
> منطق داخلی باینری را تغییر ندهید (ممکن و مجاز نیست).**

از شما چند خواسته‌ی مشخص نشنیده‌ام (لوگو؟ رنگ؟ دامنه؟ اتصال به سایت؟).
در پایان این سند فهرست سوالات را گذاشته‌ام تا دقیق برای همان جلسه‌ی بعدی پیاده‌سازی کنیم.

## لایه ۱ — تنظیمات رسمی پشتیبانی‌شده (`config.yml` + پنل)

| کار | کجا | چطور |
|---|---|---|
| تغییر دامنه | رکورد A/AAAA دامنه → IP سرور، و سپس اجرای مجدد با `auto_ssl: true` (برای صدور گواهی جدید) | DNS + `config.yml` |
| روشن/خاموش SSL خودکار | `config.yml` → `auto_ssl: true/false` | متن: `deploy/config.yml.example` |
| تعیین secret برای API | `config.yml` → `secret: "..."` (همان مقداری که در درخواست‌های `MeetList`/`ActiveMeets` و هر API دیگری که بخواهید secret بخواهد می‌فرستید) | متن: `deploy/config.yml.example` |
| تعیین اینکه کدام API ها secret بخواهند | خود `config.yml` (طبق سند api/intro این انتخاب در همان فایل است) | همان فایل |
| تغییر رمز ادمین پیش‌فرض (`admin/1111`) | پنل وب بعد از اولین ورود → بخش تنظیمات/کاربران (این کار **اولین قدم بعد از نصب** باشد) | مرورگر |
| تغییر ظرفیت اتاق‌ها / رمز اتاق | هنگام ساخت اتاق از پنل یا از طریق API (`UserCount`, `UserPass`, …) | API |

## لایه ۲ — برندینگ ظاهری بدون دست‌بردن در باینری

> **جدید:** برند را به‌صورت **پویا و از داخل پنل ادمین محصول** تنظیم کنید (نام/توضیح/رنگ/آیکون/لوگو با آپلود فایل):
> [`13-branding.md`](13-branding.md) — این روش بر ویرایش دستی فایل‌ها ارجحیت دارد.

> مستندات رسمی می‌گویند: «You can personalize everything, from URLs to logos and branding colors, as well as features with ease.»
> یعنی سازنده انتظار دارد ظاهر شخصی شود. دو مسیر دارید:

### روش الف) ویرایش فایل‌های استاتیک پکیج (اگر روی دیسک هستند)

```bash
ls -la /opt/persianmeet            # محتویات پکیج بعد از unzip
find /opt/persianmeet -maxdepth 3 -type d | sort
find /opt/persianmeet -iname "*.html" -o -iname "*.css" | head -30
```

- لوگوی جدید را جایگزین کنید (همان نام فایل قدیمی را نگه دارید).
- رنگ‌ها را در CSS ویرایش کنید.
- ⚠️ قبل از هر آپدیت، فایل‌های تغییرکرده را با `deploy/backup.sh` بکاپ بگیرید؛ بعد از دانلود نسخه‌ی جدید بازنویسی می‌شوند.

### روش ب) تزریق تغییرات در لبه‌ی Nginx — حتی اگر فایل‌ها داخل باینری باشند (پیشنهادی)

با گذاشتن Nginx جلوی PersianMeet (نمونه‌ی کامل: `deploy/nginx.reverse-proxy.conf`) می‌توانید بدون تماس با فایل‌های فروشنده، ظاهر را بازسازی کنید:

```nginx
# مثال: جایگزینی لوگو و تزریق CSS دلخواه
proxy_set_header Accept-Encoding "";   # برای این‌که sub_filter روی متن کار کند
sub_filter 'src="/assets/logo.svg"' 'src="/branding/logo.svg"';
sub_filter '</head>' '<link rel="stylesheet" href="/branding/brand.css"></head>';
sub_filter_once off;
```
و فایل‌های خودتان (`logo.svg`, `brand.css`) را در همان Nginx سرو کنید:

```nginx
location /branding/ { root /opt/branding; }
```

**مزیت:** هیچ فایل فروشنده‌ای دست‌نخورده باقی می‌ماند؛ با هر آپدیت، فقط این vhost را نگه می‌دارید.
**محدودیت:** فقط متون/URLهای **متنی** قابل تعویض‌اند (نه منطق JS مینی‌فای/فشرده).

## لایه ۳ — یکپارچه‌سازی با سایت و سامانه‌ی شما (API رسمی)

این قدرتمندترین «تغییر» است: کاربران شما بدون اینکه PersianMeet را ببینند، از سرویس شما وارد اتاق می‌شوند.

نمونه‌ی کامل در [`api/README.md`](../api/README.md). سه الگوی رایج:

1. **ساخت اتاق هنگام ساخت دوره/کلاس در پنل شما** → `CreateMeet`
2. **ساخت لینک ورود شخصی برای هر دانشجو** → `Join` (با `JoinRole: 0` برای دانشجو و `1` برای مدرس) و نمایش `Url` خصوصی در پنل کاربر
3. **گزارش‌گیری** → `ActiveMeets` / `MeetList` / `GetMeetInfo` (با secret)
4. **پاک‌سازی خودکار بعد از ترم** → `DeleteMeet` (⚠️ غیرقابل بازگشت)

نمونه‌ی PHP خلاصه (خودتان می‌توانید همین ایده را در لاراول/وردپرس پیاده کنید):

```php
$ch = curl_init('https://class.example.com/api');
curl_setopt_array($ch, [
  CURLOPT_RETURNTRANSFER => true,
  CURLOPT_POST => true,
  CURLOPT_HTTPHEADER => ['Content-Type: application/json'],
  CURLOPT_POSTFIELDS => json_encode([
    'Type' => 'CreateMeet',
    'Data' => ['Title' => $courseName, 'UserNeedPass' => false,
               'AdminNeedPass' => true, 'AdminPass' => $adminPass, 'UserCount' => 100],
  ]),
]);
$res = json_decode(curl_exec($ch), true);   // ['Status'=>'ok','ID'=>21,'Url'=>'/room/21', ...]
```

## لایه ۴ — زیرساختی (برای سرور تمیز و امن)

- **systemd** به‌جای `./persianmeet &` → ری‌استارت خودکار، لاگ با journalctl (`deploy/persianmeet.service`)
- **فایروال**: فقط ۲۲ (SSH)، ۸۰، ۴۴۳ باز باشد؛ اگر WebRTC/SFU روی UDP کار می‌کند، بازه‌ی مربوطه را باز کنید (`ss -tulpn` بعد از نصب واقعی)
- **بکاپ**: `deploy/backup.sh` پوشه‌ی فایل‌ها + `config.yml` را می‌گیرد (به کراون اضافه کنید)
- **به‌روزرسانی**: `deploy/update.sh` نسخه‌ی جدید را دانلود می‌کند (config شما را حفظ می‌کند)
- **لاگ**: `journalctl -u persianmeet -f`

## لایه ۵ — تغییر «منطق داخلی» باینری؟ ممنوع/ممکن نیست

- سورس بک‌اند PersianMeet **عمومی نیست** و مجوزی برای دی‌کامپایل/ویرایش/بازتوزیع باینری به شما داده نشده است.
- این ریپو عمداً هیچ فایل باینری یا کدی از محصول را شامل نمی‌شود.
- اگر به سطح عمیق‌تری نیاز دارید، دو راه دارید:
  1. **مذاکره با سازنده** برای لایسنس سورس/تجاری (از طریق وب‌سایت رسمی learn100.ir).
  2. رفتن سراغ بستر **کاملاً متن‌باز** (پایین را ببینید).

## اگر «سورس کامل در دستم باشد» برایتان خط‌قرمز است

| جایگزین | چرا | نکته |
|---|---|---|
| **BigBlueButton** | کلاس مجازی کامل، واقعاً متن‌باز (LGPL)، وایت‌برد، نظرسنجی، اشتراک صفحه | سنگین‌تر (۸+ گیگ رم توصیه می‌شود) |
| **Jitsi Meet** | ساده، متن‌باز (Apache-2.0)، کیفیت ویدئو عالی | امکانات آموزشی کمتر از BBB |
| **LiveKit** | زیرساخت WebRTC/SFU بسیار مدرن، متن‌باز (Apache-2.0) | شما باید اپ/UI خودتان را بسازید |
| **Rocket.Chat (Voice/Jitsi)** | متن‌باز | تمرکز روی چت است |

و یادآوری: فرانت‌اندهای پابلیک سازنده در گیت‌هاب (`meet-react`, `meet-connect`, `aimeet`) **پروتوتایپ/ماکت هستند** (داده‌ی fake با `simulation.ts` و `seed.ts`) و بدون LICENSE منتشر شده‌اند؛ آن‌ها جایگزین محصول آماده نیستند و کپی آزاد از آن‌ها در پروژه‌ی شما مجاز نیست.

## سوالات کلیدی برای پیاده‌سازی ادامه‌ی کار

1. دقیقاً چه تغییری می‌خواهید؟ (لوگو/رنگ/نام/لینک؟ زبان فارسی/انگلیسی؟ حذف اسم "PersianMeet"؟)
2. کاربران شما از کجا وارد می‌شوند؟ (سایت وردپرس؟ لاراول؟ فروشگاهی؟ دسترسی مستقیم با لینک؟)
3. دامنه دارید؟ DNS به این سرور می‌آید؟ (برای `auto_ssl` لازم است)
4. حجم و تعداد کاربر هم‌زمان چقدر است؟ (برای تنظیم UDP/SFU و فایروال)
