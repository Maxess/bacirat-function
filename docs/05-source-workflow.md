# کار با سورس اصلی PersianMeet (برای شما که لایسنس سورس دارید)

> شما به سازنده اعلام کرده‌اید سورس را دارید و می‌توانید تغییر دهید. این سند برنامه‌ی عمل برای اعمال
> خواسته‌های شما روی همان سورس است + ابزاری که مستقل از سورس کار می‌کند (`classroom-manager/`).

## قدم ۱ — سورس را کجا بگذاریم؟

**هرگز سورس را داخل گیت همین ریپو commit نکنید.** دو راه امن:

1. **همین ماشین — پوشه‌ی محلی و خارج از git** (پیش‌فرض): سورس را در `<repo>/persianmeet-src/` استخراج کنید.
   این پوشه از قبل در `.gitignore` است. من هم همین‌جا روی آن کار می‌کنم.
2. **ریپوی خصوصی جدا برای سورس**: اگر می‌خواهید سورس در git باشد، یک ریپوی خصوصی جدید
   (مثلاً `Maxess/persianmeet-internal`) بسازید و سورس را آنجا commit کنید؛ سپس آن را به‌صورت submodule
   در همین ریپو وصل کنیم. (حتی خصوصی هم هست، انتقال سورس به گیت‌هاب باید طبق مجوز سازنده باشد —
   اگر مجوز فقط «روی سرور خودتان» است، راه ۱ را انتخاب کنید.)

## قدم ۲ — تشخیص پشته و ساختن پروژه

بعد از استخراج، بگویید یا خودتان این‌ها را اجرا کنید:

```bash
cd persianmeet-src
ls
find . -maxdepth 2 \( -name "*.sln" -o -name "*.csproj" -o -name "go.mod" -o -name "package.json" -o -name "*.proto" \) | head -20
```

نشانه‌های رایج:

| نشانه | پشته | ابزار build |
|---|---|---|
| `*.sln` / `*.csproj` | ASP.NET Core (سی‌شارپ) | `dotnet build` / `dotnet run` |
| `go.mod` | Go (تک‌باینری) | `go build` |
| پوشه‌ی `wwwroot/` با HTML/JS | فرانت‌اند استاتیک (همان چیزی که مرورگر می‌بیند) | ویرایش مستقیم / باندلر |
| `*.proto` | تعریف پیام‌های protobuf برای `/wsroom` | `protoc` |

## قدم ۳ — نقشه‌ی پیاده‌سازی خواسته‌های شما روی سورس

| خواسته | لایه | روش پیشنهادی |
|---|---|---|
| **۱) برندینگ — لوگو، رنگ، متن‌ها** | `wwwroot` (استاتیک) | جایگزینی لوگو/CSS/متن‌ها؛ یا تزریق از Nginx (`docs/02` § روش ب). سریع‌ترین و بی‌خطرترین تغییر. |
| **۲) ایمپورت دانش‌آموزان/دبیران با CSV** | بک‌اند (+پنل مدیریت) | الف) **بدون لمس سورس (همین حالا آماده است):** ماژول `classroom-manager` با CSV فارسی `teachers.csv / students.csv / classes.csv`.<br>ب) در سورس: یک صفحه/endpoint جدید روی الگوی آپلودهای موجود در پنل ادمین اضافه کنید (parse → validate → insert با transaction). دنبال الگو بگردید: `grep -ri "upload\|import" --include=* -l` |
| **۳) سیستم ورود دانش‌آموز/دبیر** | بک‌اند — ماژول auth | در سورس جدول‌ها/نقش‌ها را پیدا کنید: `grep -ri "joinrole\|adminuser\|role" -l`. ورود دبیر با حساب واقعی + ورود دانش‌آموز فقط با لینک/کد کلاس (role=0). نمونه‌ی کامل در `classroom-manager` پیاده شده است. |
| **۴) تعریف دانش‌آموزان هر کلاس + فعال‌سازی با ورود دبیر + بستن کلاس و خروج همه** | بک‌اند — چرخه‌ی اتاق | **همین حالا با `classroom-manager`**: شروع کلاس دبیر → اتاق PersianMeet ساخته می‌شود، لینک خصوصی دبیر و هر دانش‌آموز صادر می‌شود؛ «بستن کلاس» دبیر → حذف/توقف اتاق (`DeleteMeet` یا فقط علامت‌گذاری بسته طبق تنظیم) → همه از کلاس بیرون می‌افتند. برای «قطع فوری همه» بدون حذف اتاق، در سورس یک broadcast روی hub بفرستید (پایین‌تر). |
| **۵) حضور و غیاب لحظه‌ای + مدت حضور** | بک‌اند — presence روی `/wsroom` | در سورس، connection manager/hub را پیدا کنید (`grep -ri "wsroom\|centrifugo\|hub\|connection" -l`). روی رویدادهای **connect/disconnect/heartbeat** ثبت کنید: `attendance_log(meet_id, pid, name, role, joined_at, left_at)`. هر heartbeat آنلاین بودن را تمدید می‌کند. خروجی دقیق per-user با این patch به دست می‌آید. (در v1 ما بیرونی، ورود دقیق از مسیر `/enter` ثبت می‌شود و خروج = زمان بستن کلاس.) |
| **۶) تخته تعاملی + کتاب PDF + ورق‌زدن برای تدریس** | فرانت‌اند (تخته) + بک‌اند (تبدیل صفحه) | الفٔ پیدا کردن کامپوننت تخته: `grep -ri "whiteboard\|canvas\|board" --include=*.{js,ts,tsx,razor,cshtml} -l`<br>ب) بک‌اند: رندر صفحات PDF با `mutool`/`mudraw` (پکیج `mupdf-tools` از قبل وابستگی رسمی است) — هر صفحه به یک PNG/JPEG در `wwwroot/files/books/<id>/` تبدیل شود.<br>ج) فرانت: pod «کتاب» اضافه کنید: فایل را آپلود کنید، صفحات را اسلایدکنید، «صفحه بعد/قبل» دبیر برای همه‌ی شرکت‌کنندگان از طریق همان کانال `/wsroom` (پیام prototype جدید مثل `BookPageChanged { page }`) broadcast شود.<br>د) نام‌گذاری پیام‌ها و sync را دقیقاً روی الگوی پیام‌های موجود whiteboard کپی کنید. |

## قدم ۴ — گردش کار پیشنهادی در سورس

```bash
cd persianmeet-src
git init && git add -A && git commit -m "upstream v0.26.3 (unmodified)"   # اگر سورس بدون تاریخچه گرفتید
git switch -c feature/csv-import
# ... پیاده‌سازی ...
go test ./...   # یا dotnet test
```

- هر خواسته = یک commit/branch جدا (`feature/csv-import`, `feature/attendance`, `feature/pdf-book`, `feature/kick-all-on-close`).
- قبل از ادغام، روی یک نسخه‌ی staging کنار نسخه‌ی پروداکشن تست کنید (پورتی دیگر + دامنه‌ی دیگر).
- پس از ادغام، باینری/پکیج جدید را با همان فرایند `deploy/update.sh` روی سرور اصلی ببرید (بکاپ خودکار).

## قدم ۵ — چه چیزی همین حالا (بدون سورس) آماده است؟

پوشه‌ی **`classroom-manager/`** در این ریپو دقیقاً خواسته‌های ۲، ۳ و ۴ و بخش ورودِ ۵ را به‌صورت یک سرویس مستقل و قابل اجرا پیاده می‌کند:

- ایمپورت CSV معلمان/کلاس‌ها/دانش‌آموزان (با گزارش خطای هر ردیف)
- ورود دبیر/مدیر، شروع کلاس → ساخت اتاق PersianMeet + لینک خصوصی دبیر و هر دانش‌آموز
- لینک ورود دانش‌آموز از مسیر `/enter` ما رد می‌شود تا **زمان ورود واقعی** ثبت شود
- بستن کلاس توسط دبیر → ثبت خروج همه + توقف/حذف اتاق
- گزارش حضور (کد، نام، ورود، خروج، مدت) + خروجی CSV

یعنی حتی قبل از اینکه سورس را لمس کنید، فرایند کامل «دبیر وارد می‌شود کلاس فعال می‌شود / دبیر می‌بندد همه خارج می‌شوند + حضور و غیاب زمان‌دار» کار می‌کند.

## چیزهایی که به سورس نیاز دارند (در صف بعدی)

- خروج آنی هر دانش‌آموز در لحظه‌ی بستن کلاس (بدون حذف اتاق) → broadcast در hub
- حضور دقیق per-user در لحظه (آنلاین/آفلاین زنده + مدت دقیق) → patch رویدادهای presence
- کتاب PDF روی تخته → patch فرانت (pod کتاب) + بک (تبدیل صفحه با mupdf)

**خروجی لازم از شما برای ادامه:** یا سورس را در `persianmeet-src/` روی همین ماشین بگذارید/آپلود کنید
(یا push کنید به ریپوی خصوصی جدا)، یا حداقل نوع پشته (Go یا ASP.NET؟ نسخه؟) و ساختار پوشه‌ی اصلی را بفرستید.
