# نصب نسخهٔ ۱٫۳٫۰ کلاس مجازی Baci — زنده، ضبط و تحویل فیلم

**اول از VPS و سایت مدرسه پشتیبان خصوصی بگیر؛ پیش از آماده‌بودن بسته، DNS و مسیر HTTPS سرور را ریست نکن.** این بسته برای VPS رسانه و ضبط است؛ سایت Baci با PHP/MySQL در جای خودش می‌ماند. رندر روی همان VPS انجام می‌شود و نیاز به VPS دوم، CDN خارجی یا دانلود کتابخانه از VPS ندارد. اجرای کلاس همچنان به ارتباط دستگاه‌ها با VPS و سایت، و ارسال فیلم به ارتباط با پیام‌رسان انتخاب‌شده نیاز دارد.

## ۱. پیش از ریست یا نصب، این موارد را آماده کن

- تصویر رسمی **Ubuntu 24.04 LTS amd64 / x86_64** با systemd و cgroup v2، دسترسی `sudo` یا root و IPv4 قابل‌دسترسی برای دستگاه‌ها. این بسته نصب‌کنندهٔ سیستم‌عامل نیست؛ ARM، Windows، کانتینر محدود یا توزیع دیگری را با این فایل نصب نکن. پیش از بارگذاری آرشیو و بعد از اختصاص swap، دست‌کم **۸ GiB فضای خالی** روی دیسک سیستم در نظر بگیر؛ بایگانی موقت کلاس‌های طولانی فضای بیشتری می‌خواهد.
- **نام مستقل رسانه**، مثلاً `class.example.ir`، با رکورد `A` مستقیم به IPv4 VPS. برای آن نام Proxy/CDN یا رکورد `AAAA` باقی نگذار. نشانی مدرسه HTTPS و جداست؛ زیرپوشهٔ واقعی مثل `/baci` را در نشانی مدرسه بنویس.
- در فایروال پنل و Ubuntu، `443/TCP` برای HTTPS و WebSocket، `7882/UDP` برای رسانهٔ ترجیحی و `7881/TCP` برای مسیر جایگزین رسانه. [دو مرورگر روی ۷۸۸۱](https://github.com/Maxess/bacirat-function/actions/runs/45727830890) با UDP بسته، صدای دوطرفه و تصویر دبیر را دریافت کردند؛ این آزمون تضمین ظرفیت TCP یا عبور از همهٔ فایروال‌ها نیست. `7880` و `7883` خصوصی‌اند؛ بازشان نکن. پورت ۸۰ لازم نیست. اگر `443/TCP` به VPS نمی‌رسد یا هیچ مسیر رسانه قابل‌دسترسی نیست، اول با ارائه‌دهنده هماهنگ کن. یک پورت تصادفی جایگزین HTTPS یا ICE اعلام‌شده به مرورگر نمی‌شود. نصب‌گر سرویس فعلی یا فایروال را برای آزاد کردن پورت دستکاری نمی‌کند.
- از [انتشار ۱٫۳٫۰](https://github.com/Maxess/bacirat-function/releases/tag/vps-offline-v1.3.0) این سه فایل را روی رایانه بگیر: [آرشیو نصب](https://github.com/Maxess/bacirat-function/releases/download/vps-offline-v1.3.0/baci-classroom-vps-offline-v1.3.0-ubuntu24.04-amd64.tar.gz)، [اسکریپت نصب](https://github.com/Maxess/bacirat-function/releases/download/vps-offline-v1.3.0/install-vps.sh) و [فایل هش‌ها](https://github.com/Maxess/bacirat-function/releases/download/vps-offline-v1.3.0/baci-classroom-vps-offline-v1.3.0-ubuntu24.04-amd64-SHA256SUMS.txt). `baci-prepare-swap.sh` فقط برای پلان کم‌حافظه‌ای است که swap لازم را ندارد. فایل‌های `ubuntu-source` برای نصب لازم **نیستند**. ZIP جفت‌سازی تنها در صورت نیاز به به‌روزرسانی سایت لازم است.

### انتخاب RAM و CPU برای ضبط

**پیشنهاد برای شروع: ۱ GiB RAM و دست‌کم یک vCPU روی VPS اختصاصی**، با `compact`. اگر حداقل هزینه مهم‌تر است، مسیر سنجیده‌شده روی ۵۱۲ MiB/یک vCPU و swap هم ضبط دارد، ولی حاشیهٔ کمتری برای کلاس طولانی و بار هم‌زمان دارد. `full` با ۴ GiB هم آزموده شده است. نام نسل یا برند CPU جای آزمون عملی مرورگر و رمزگذار را نمی‌گیرد: نصب‌گر پیش از اعلام موفقیت یک MP4 آزمایشی می‌سازد.

| RAM قابل‌مشاهده در `MemTotal` | انتخاب پیش‌فرض `install-vps.sh` |
|---|---|
| حداقل `1792 MiB` | `full` — کلاس، ضبط، رندر و ارسال با فضای حافظهٔ بیشتر |
| از `896 MiB` تا کمتر از `1792 MiB` | `compact` — همان مسیر ضبط، با رندر کم‌مصرف؛ swap اجباری نیست |
| از `448 MiB` تا کمتر از `896 MiB` | `compact` با حداقل `512000 KiB` swap فعال؛ فایل swap اسمی ۵۱۲ MiB کافی است |
| کمتر از `448 MiB` | برای ضبط کافی نیست؛ نصب سبک `--profile live` فقط با انتخاب صریح و حداقل `384 MiB` ممکن است و فیلم تولید نمی‌کند |

این جدول برای `install-vps.sh` همراه انتشار است، نه `auto` تاریخی داخل آرشیو. برای حفظ همان بایت‌های آزموده‌شده، متن داخل آرشیو بازنویسی نشده است؛ **راهنمای فعلی را ملاک بگیر.** اگر تصمیم داری خودت از داخل آرشیو نصب کنی، `--profile compact` یا `--profile full` را صریح بده. این حدود به **RAMی که لینوکس می‌بیند** مربوط است؛ RAM رزروشدهٔ هسته و swap جای آن را نمی‌گیرند. برای خواندن وضعیت:

```bash
grep -E '^(MemTotal|SwapTotal):' /proc/meminfo
```

در پلان ۵۱۲ MiB با RAM کافی، اگر swap فعال لازم است، اول گزینهٔ swap ارائه‌دهنده را بررسی کن. روی Ubuntu اختصاصی با ext4 یا XFS، ابزار آفلاین بسته هم می‌تواند یک swapfile اختصاصی بسازد. فرمان‌های زیر را بعد از انتقال و بررسی هش ابزار در بخش ۲ اجرا کن. `--check` فقط گزارش می‌دهد و `--apply` را خودت تأیید می‌کنی؛ هیچ swap قبلی، `fstab`، سیاست حافظهٔ هسته یا سرویس کلاس را تغییر نمی‌دهد:

```bash
sudo bash ./baci-prepare-swap.sh --check
# فقط در صورت swap=would_create و اگر می‌خواهی ۵۱۲ MiB دیسک اختصاص یابد:
sudo bash ./baci-prepare-swap.sh --apply
```

## ۲. بسته را از مسیر در دسترس منتقل کن

**مطمئن‌ترین مسیر اگر VPS به GitHub یا CDN دسترسی ندارد:** با **SFTP**، آرشیو، اسکریپت نصب و فایل هش‌ها را به یک پوشهٔ تازه در خانهٔ کاربر SSH بفرست. هنگام اتصال، اثر انگشت SSH را با پنل ارائه‌دهنده تطبیق بده. نیاز نیست فایل را در FileZilla از حالت فشرده خارج کنی. از همان پوشه در SSH کار کن؛ نام آرشیو را تغییر نده. هش‌های اسکریپت، آرشیو و ابزار swap (اگر استفاده می‌کنی) را با فایل انتشار مقایسه کن. خود اسکریپت هم قبل از اجرای نصب‌گر با root، هش ثابت آرشیو را بررسی می‌کند. برای بررسی فایل‌هایی که به همان پوشه آورده‌ای (فایل‌های منبع لازم نیستند):

```bash
sha256sum --strict --check --ignore-missing baci-classroom-vps-offline-v1.3.0-ubuntu24.04-amd64-SHA256SUMS.txt
```

باید `OK` برای هر فایل دریافت‌شده ببینی. در PowerShell می‌توانی `Get-FileHash -Algorithm SHA256 -Path 'نام فایل'` را با سطر متناظر تطبیق بدهی.

**مسیر آنلاین اختیاری:** اگر VPS به فایل‌های انتشار دسترسی دارد، فقط اسکریپت تأییدشده را بفرست و `bash ./install-vps.sh --check` بزن. اگر آرشیو رسمی کنار آن در پوشهٔ جاری باشد، همان استفاده می‌شود؛ در غیر این صورت از GitHub Releases دریافت می‌شود. اگر کپی همان آرشیو را روی آینهٔ HTTPS داخلی گذاشته‌ای، می‌توانی از `--mirror 'https://mirror.example.ir/path/baci-classroom-vps-offline-v1.3.0-ubuntu24.04-amd64.tar.gz'` استفاده کنی. آینه نمی‌تواند هش یا محتوای نسخه را عوض کند. هیچ مسیری `curl -k` یا `curl | bash` لازم ندارد.

## ۳. SSL و نصب را بررسی و اجرا کن

### انتخاب SSL: مستقل از روش دانلود

- **صدور خودکار:** اگر شبکه اجازه می‌دهد، همان حالت پیش‌فرض را بدون فایل PEM بزن یا `--tls auto` را اضافه کن. Caddy گواهی عمومی Let’s Encrypt را از طریق TLS-ALPN-01 روی **TCP 443** نصب و تمدید می‌کند. ساعت، DNS، خروجی معتبر HTTPS به مرجع صدور و دسترسی آن مرجع به ورودی ۴۴۳ لازم‌اند. نبودن CDN به این مسیر ربطی ندارد؛ دسترسی به **مرجع صدور** شرط جداست.
- **نصب آفلاینِ SSL:** اگر VPS به مرجع صدور نمی‌رسد، از سرویس میزبانی/مرجع مورد اعتمادت گواهی عمومی **همان نام رسانه**، زنجیرهٔ کامل `fullchain.pem` و کلید متناظر `privkey.pem` را بگیر. فایل‌ها را کنار آرشیو با SFTP منتقل کن و `chmod 600 privkey.pem` بزن. کلید PEM بدون عبارت رمز لازم است و نباید symlink باشد. نصب‌گر با یافتن هر دو، حالت `files` را خودکار برمی‌گزیند؛ می‌توانی `--tls files` را هم صریح بدهی. hostname، گواهی، اعتماد، ساعت و هم‌خوانی کلید بررسی می‌شوند. تمدید این مسیر را باید صادرکننده یا مدیر گواهی انجام دهد. اگر فایل‌ها نام دیگری دارند `--tls files --cert ./chain.pem --key ./key.pem` بده. گواهی خودامضا، گواهی مخصوص پشت CDN یا نادیده گرفتن اخطار TLS جایگزین نیست. وقتی هیچ مرجع مورد اعتماد در دسترس نیست و گواهی معتبری هم نداری، SSL عمومی را نمی‌شود خودکار ایجاد کرد.

### دو فرمان روی VPS تازه

```bash
# در همان پوشه‌ای که آرشیو و install-vps.sh را بارگذاری کرده‌ای:
bash ./install-vps.sh --check
```

سه ورودی را بده: **نشانی HTTPS سایت**، **نام رسانه بدون `https://` یا پورت**، و **IPv4 VPS**. با `--site`، `--media` و `--ipv4` هم می‌توانی همان‌ها را بدهی. اگر `preflight=ok` و `profile=compact` یا `profile=full` دیدی، با همان ورودی‌ها اجرا کن:

```bash
bash ./install-vps.sh
```

حالت SSL و پروفایل اگر نیاز است در هر دو فرمان یکسان تعیین شوند. پیش‌بررسی سرویس، جفت‌سازی یا سفارش گواهی ایجاد نمی‌کند. در حالت `files` برای نصب به DNS عمومی مراجعه نمی‌کند؛ حتی پیش‌بررسی موفق جای آزمون ورودی عمومی، مرورگر و تحویل فیلم نیست. اجرای واقعی وابستگی‌ها را فقط از بسته می‌خواند، سرویس‌ها را نصب می‌کند و رندر MP4 در sandbox و HTTPS را می‌آزماید. موفقیت مورد انتظار: `installation=ok ... renderer_mp4=ok`. پس از تکمیل:

```bash
sudo baci-vps doctor
```

### اگر VPS ۱٫۲٫۰ در حالت `live` سالم است و نمی‌خواهی ریست کنی

بعد از بستن زنگ‌ها، تمام‌شدن صف فیلم و تهیهٔ پشتیبان، از **همین بستهٔ جدید** و مسیر افزودن ضبط استفاده کن. جفت‌سازی قبلی باید روی سایت برقرار و ضبط در پنل مجاز باشد. `--site`، `--media`، `--ipv4`، `--tls` یا فایل جدید SSL نده؛ تنظیمات قبلی حفظ می‌شوند:

```bash
bash ./install-vps.sh --add-recorder --check
# پس از add_recorder_preflight=ok:
bash ./install-vps.sh --add-recorder
```

مسیر افزودن ضبط در QA روی یک GiB بدون swap، با رد درخواست مدرسه و برگشت موفق و سپس نصب بدون راه‌اندازی مجدد سرویس‌های زنده بررسی شده است. اجرای دوبارهٔ مسیر **نصب تازه** جای `--add-recorder` نیست.

## ۴. مدرسه، ضبط و گروه را وصل و آزمایش کن

1. در **مدیر افزونه‌ها ۰٫۱٫۳۱ / کلاس مجازی ۰٫۴٫۲۴**، از «تنظیمات دیگر ← افزونه‌ها ← کلاس مجازی ← اتصال یک‌مرحله‌ای VPS جدید» فایل خصوصی `Baci-VPS-pairing.json` را فقط از طریق پنل HTTPS مدیر کل وارد کن و افزونه را فعال کن. نصب تازه یا ریست VPS کلیدهای تازه می‌سازد؛ جفت‌سازی قبلی کار نمی‌کند. در افزودن ضبط به VPS موجود، فایل جدید وارد نکن. اگر فایل صادر نشده، با حساب SSH خودت `sudo baci-vps export` را بزن؛ فایل موجود بازنویسی نمی‌شود. کلید، فایل جفت‌سازی و توکن ربات را در چت یا وب‌ریشه نگذار. برای نصب تازهٔ سایت، بخش‌های ۲، ۳ و ۵ [راهنمای سایت پایه و جفت‌سازی](https://github.com/Maxess/bacirat-function/blob/bd832cb6ea00dbf123985b1023273046c8999133/server/offline/README-fa.md) را بخوان؛ اگر سایت سالم است آن را از نو نصب نکن.
2. مطمئن شو Cron **CLI هاست مدرسه** هر دقیقه برقرار است. نمونه برای سایت در زیرمسیر `/baci`: `/usr/bin/php /home/CPUSER/public_html/baci/plugins/school-plugins.php classroom-job /baci`. مسیر PHP، کاربر و مسیر فایل را با مقدار واقعی عوض کن. اگر سایت در ریشهٔ URL است، آرگومان آخر را حذف کن. این Cron روی VPS رسانه نیست.
3. ضبط اختیاری را در پنل فعال کن. از بیرون VPS، `https://نام-رسانه/healthz` باید بدون خطای گواهی باز شود. سپس `sudo baci-vps doctor --online` را اجرا کن؛ انتظار `school_webhook=ok` و پس از رسیدن heartbeat، `school_recorder=ready` است.
4. برای مقصد داخل کشور، ربات **بله** یا **روبیکا** را در سایت و گروه آزمایشی ثبت کن؛ ربات باید اجازهٔ ارسال ویدیو داشته باشد. در «گروه‌های پیام‌رسان و ضبط کلاس» همان گروه را به کلاس پیوند بده. سایت و VPS باید به API پیام‌رسان انتخابی برسند؛ روبیکا برای آپلود از میزبان فایل هم استفاده می‌کند. اگر مسیر پیام‌رسان قطع است، نصب و رسانه به آن وابسته نیستند، ولی تحویل فیلم به آن گروه ممکن نیست؛ وضعیت صف و مقصد را در پنل ببین. مقصد را بدون اجازهٔ مدیر عوض نکن.
5. با حساب دبیر و دانش‌آموز از دو دستگاه و ترجیحاً دو شبکه در یک **زنگ عادی آزمایشی** وارد شو. صدا، دوربین، اشتراک صفحه و تخته/PDF را بررسی کن. با اطلاع و رضایت افراد ضبط را شروع کن؛ حالت جمعه برای آزمون ضبط نیست. دبیر «بستن کلاس برای همه» و سپس «بله» برای ارسال را انتخاب کند. ساخت پس از تأخیر مدرسه (پیش‌فرض **۱۸۰ دقیقه** پس از پایان واقعی، در تنظیمات قابل تغییر) و وقتی زنگ فعالی نیست آغاز می‌شود. برای تمرین جداگانه می‌توانی موقتاً تأخیر کوتاه‌تری تنظیم کنی. دریافت و پخش MP4 را در **همان گروه** ببین؛ یک زنگ جدا هم با «خیر» ببند و نبود ارسال را تأیید کن.

## اگر یک مرحله رد شد

| نشانه | مسیر امن بعدی |
|---|---|
| دانلود قطع شد یا سایت GitHub از VPS باز نمی‌شود | انتقال SFTP همان آرشیو، یا HTTPS آینهٔ داخلی؛ از همان هش بررسی‌شده استفاده کن. |
| `SHA-256` یا `Bundle integrity` | نصب انجام نمی‌شود. دوباره از فایل انتشار بگیر؛ فایل‌های PEM را داخل درخت استخراج‌شده نگذار. |
| خطای RAM/swap | اندازه‌های بالا را مقایسه کن؛ swap اختصاصی با تأیید خودت یا گزینهٔ ارائه‌دهنده. برای داشتن ضبط `live` را به‌عنوان «رفع خطا» انتخاب نکن. |
| `Port … is already in use` یا `healthz` از بیرون باز نیست | مسیر TCP 443 و پورت‌های رسانه را با پنل و ارائه‌دهنده بررسی کن. سرویس دیگر را کورکورانه متوقف نکن. TCP رسانهٔ ۷۸۸۱ جای HTTPS ۴۴۳ نیست. |
| `Media DNS is not ready` | رکورد `A` مستقیم و تنها به IPv4 صحیح، بدون `AAAA` و proxy. بررسی روی خود VPS همیشه معادل دید عمومی نیست. |
| خطای ACME، ساعت یا TLS | ساعت و دسترسی بیرونی ۴۴۳، DNS و CAA را بررسی کن. اگر صدور در شبکه ممکن نیست، `files` با زنجیرهٔ معتبر استفاده کن؛ پشت سر هم سفارش گواهی نده. |
| `Not enough free space` / خطای استخراج | فضای دیسک سیستم و پارتیشن موقت را پیش از تلاش دوباره بررسی کن؛ آرشیو و فایل‌های موقت استخراج در زمان نصب هم‌زمان جا می‌خواهند. |
| `Packages need to be removed but remove is disabled` | نصب‌گر برای حفظ بسته‌های Ubuntu متوقف شده است. هشدار `/etc/apt/-/` علت توقف نیست و نباید آن پوشه را ساخت. در ۱٫۳٫۰، از [ابزار تشخیص APT](../scripts/diagnose-vps-apt.sh) با **همان آرشیو** استفاده کن؛ `bash diagnose-vps-apt.sh` در پوشهٔ آرشیو، بدون sudo، طرح واقعی را شبیه‌سازی می‌کند. سطرهای `Remv` و `Broken` نشان می‌دهند کدام بسته‌ها و نسخه‌ها ناسازگارند. بدون دانستن آن‌ها حذف، downgrade یا ریست نکن. |
| سایر خطاهای `Offline APT` | روی Ubuntu رسمی amd64 و بدون apt هم‌زمان امتحان کن. رفع ناسازگاری بسته‌ها را جدا از نصب کلاس انجام بده. ممکن است پس از شکست در مراحل بعدی، پیش‌نیازهای نصب‌شده باقی بمانند. |
| `renderer` / خطای MP4 در پیش‌نیاز ضبط | Ubuntu و قابلیت sandbox/cgroup را بررسی کن، حد RAM/swap را با جدول تطبیق بده و روی VPS اختصاصی سازگار آزمون را تکرار کن. AppArmor و sandbox را خاموش نکن. |
| کلاس وصل است ولی فیلم در گروه نیست | به‌ترتیب heartbeat، ثبت گروه و اجازهٔ ربات، تأیید در **بستن عادی**، تأخیر/نبود زنگ فعال و دسترسی API/آپلود را بررسی کن. از روی `healthz` نتیجهٔ ارسال نگیر. |

**سنجش نسخه:** [آزمون بایت‌های همین آرشیو](https://github.com/Maxess/bacirat-function/actions/runs/45538814484) روی Ubuntu با ۵۱۲ MiB RAM، یک vCPU و swap، ۱۱ شرکت‌کنندهٔ مصنوعی، ضبط، تحویل MP4 قابل‌پخش، رد ارسال، لغو مقصد و بازیابی پس از reboot را گذراند. آزمون HTTPS خودکار با مرجع آزمایشی اجرای واقعی ACME انجام داد؛ دسترسی عمومی Let’s Encrypt یا API گروه واقعی روی شبکهٔ تو را تضمین نمی‌کند. این آزمون کوتاه، تضمین زنگ طولانی، چند کلاس هم‌زمان، تمام دوربین‌ها یا هر نوع VPS نیست.
