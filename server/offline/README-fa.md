# از صفر تا اولین کلاس مجازی Baci — سایت، VPS و SSL خودکار

این راهنما برای **هاست و پایگاه تازهٔ مدرسه و VPS اختصاصی تازه** است. هیچ نام دامنه، گواهی، رمز، دیتابیس یا تنظیمی از نصب قبلی لازم نیست. اگر سایت یا کلاس فعال داری، به [انتقال نصب موجود](#existing) برو؛ بستهٔ کامل سایت را روی آن باز نکن.

## ۱. دو نشانی و سه فایل آماده کن

| چه چیزی؟ | کجا؟ | نمونه؛ با نشانی خودت جایگزین کن |
|---|---|---|
| سایت و پنل Baci | هاست PHP/MySQL، مثلاً cPanel | `https://school.example.com` یا `https://school.example.com/baci` |
| رسانهٔ کلاس و ضبط | VPS اختصاصی تازه، **Ubuntu 24.04 LTS amd64 (x86_64)** | `class.example.com` و **IPv4 عمومی** که VPS به تو داده است |

این دو نام باید متفاوت باشند. مثلاً دامنهٔ سایت به هاست و رکورد `A` نام کلاس به VPS می‌رود، نه برعکس. نشانی نهایی مدرسه را یک‌بار انتخاب کن: اگر `/baci` دارد، در نصب و اتصال هم دقیقاً همان نشانی استفاده می‌شود. هاست اشتراکی فقط **سایت** را اجرا می‌کند؛ روی آن LiveKit یا نصب‌گر VPS اجرا نکن. برای VPS حداقل ۲ گیگ RAM و ۸ گیگ فضای خالی لازم است؛ برای شروع ۲ هسته، ۴ گیگ RAM و دیسک ۲۵ گیگ مناسب‌تر است. این اعداد تضمین ظرفیت کلاس نیستند.

1. **سایت پایه:** [Release_V1.15-Site.zip، نسخهٔ Baci 4.221.0، از منبع اصلی](https://github.com/mtagbot/Baci/blob/e0f3f686448642cf04ea01fcb60e79a7a786b902/Release_V1.15-Site.zip)؛ در GitHub روی **Download raw file** بزن. نسخهٔ Desktop، فایل Source code یا بستهٔ اصلاحی جایگزین این ZIP نیست. SHA-256 سایت پایه: `a394c42f5fea760ccae40b156b414c5b6e8406481fb352e0cf6084d969e5ed24`.
2. **بستهٔ اتصال سایت:** `baci-classroom-site-pairing-v0.1.31.zip` از [انتشار VPS نسخهٔ ۱٫۱٫۰](https://github.com/Maxess/bacirat-function/releases/tag/vps-offline-v1.1.0). روی **رایانهٔ خودت** این ZIP بیرونی را باز کن. دو ZIP داخلی برای **مدیر افزونه‌ها ۰٫۱٫۳۱** و **کلاس مجازی ۰٫۴٫۲۴** هستند. همین بستهٔ کوچک داخل آرشیو VPS هم هست.
3. **نصب‌گر VPS:** `baci-classroom-vps-offline-v1.1.0-ubuntu24.04-amd64.tar.gz` و فایل `SHA256SUMS.txt` با همان پیشوند از همان انتشار. بسته‌های `ubuntu-source` فقط کد منبع متناظرند؛ برای نصب لازم نیستند. **نسخهٔ قدیمی ۱٫۰٫۰ گواهی آماده می‌خواهد؛ برای SSL خودکار از ۱٫۱٫۰ استفاده کن.**

هش هر دانلود را پیش از بازکردن یا نصب مقایسه کن: در لینوکس `sha256sum نام‌فایل` و در PowerShell ویندوز `Get-FileHash -Algorithm SHA256 -Path 'نام‌فایل'`. ZIP سایت پایه جداگانه از منبع اصلی گرفته می‌شود؛ داخل انتشار VPS نیست.

## ۲. سایت مدرسه را روی هاست خالی بساز

1. در **Domains** پنل هاست، دامنه/زیردامنه و پوشهٔ عمومی اختصاصی و خالی آن را بساز (معمولاً `public_html` روی یک اکانت خالی؛ برای زیرپوشه مثلاً `public_html/baci`). رکورد DNS سایت را **طبق مشخصات هاست PHP** تنظیم کن. از **SSL/TLS Status → Run AutoSSL** یا پشتیبانی هاست برای **همین نام سایت** گواهی بگیر. با مرورگر تأیید کن `https://` بدون اخطار باز شود؛ اگر پنل گزینهٔ Force HTTPS Redirect دارد پس از فعال شدن گواهی استفاده کن. SSL مدرسه و SSL رسانه دو گواهی مستقل‌اند.
2. روی هاست از PHP تحت پشتیبانی استفاده کن (حداقل `8.1` برای سازگاری، مثلاً `8.3` تحت پشتیبانی). در **MultiPHP Manager / Select PHP Version** یا از پشتیبانی بخواه `PDO`، `pdo_mysql`، `mbstring`، `gd`، `curl`، `openssl`، `fileinfo`، `zip`، `zlib`، `dom` و نشست PHP فعال باشند. برای شروع `memory_limit` حداقل `256M`، `upload_max_filesize=20M` و `post_max_size=32M` مناسب است. حد ZIP افزونه در خود پنل ۴ مگابایت است؛ حد بزرگ‌تر PHP برای فایل‌های کلاس مثل تخته است. از میزبان MySQL/MariaDB تحت پشتیبانی ارائه‌دهنده استفاده کن.
3. در **Database Wizard / MySQL Databases** یک دیتابیس **کاملاً خالی** بساز. یک کاربر تازه با رمز جداگانه بساز و به **همان دیتابیس** اضافه کن؛ در cPanel می‌توانی `All Privileges` را فقط برای همان دیتابیس بدهی. نام کاملِ دارای پیشوند اکانت، نام کاربر، رمز، میزبان و پورت اعلامی هاست را در مدیر رمز نگه دار. معمولاً میزبان `localhost` و پورت `3306` است؛ حدس نزن اگر هاست مقدار دیگری می‌دهد. پایگاه سایت زنده یا SQL آماده را وارد نکن.
4. در **File Manager → Settings → Show Hidden Files (dotfiles)**، محتویات `Release_V1.15-Site.zip` را در ریشهٔ **همین سایت تازه** باز کن. فایل‌های `index.php`، `installer.php`، `.htaccess` و پوشهٔ `config` باید مستقیم در همان پوشه باشند، نه یک لایه پایین‌تر. ZIP را بعد از استخراج از وب‌ریشه بردار. اگر هاست در `.htaccess` خط انتخاب PHP اضافه کرده، آن را حفظ کن یا از پشتیبانی کمک بگیر. `config`، `uploads` و `backups` باید برای PHP همین حساب قابل‌نوشتن باشند؛ `777` نده.
5. **قبل از وارد کردن هر رمزی** مطمئن شو Apache/LiteSpeed قواعد `.htaccess` را اجرا می‌کند. از مرورگرِ خارج از پنل `نشانی‌سایت/config/install-access.example.php` و `نشانی‌سایت/sql/install-mysql.json` را باز کن؛ هر دو باید `403` یا `404` بدهند، نه صفحهٔ خالی `200` یا فایل قابل دانلود. `config`، `includes`، `sql`، `vendor` و `backups` باید از وب بسته باشند و اجرای اسکریپت در `uploads` ممنوع باشد. اگر میزبان Nginx است یا این آزمون رد می‌شود، ادامه نده و از پشتیبانی بخواه قبل از نصب قواعد معادل را اعمال کند.
6. در File Manager از `config/install-access.example.php` یک **کپی** با نام `config/install-access.php` بساز. در کپی، بین دو نقل‌قول `return '';` یک رشتهٔ تصادفیِ تازه، حداقل ۳۲ نویسه (مثلاً ۴۸ رقم/حرف هگز) قرار بده. از مدیر رمز استفاده کن؛ این کلید آماده ندارد و نباید در URL، چت یا اسکرین‌شات باشد.
7. `https://نشانی-واقعی-مدرسه/installer.php` را باز کن؛ اگر سایت زیرپوشه دارد، نمونه `https://school.example.com/baci/installer.php` است. کلید اجازه، مشخصات MySQL، نام مدرسه، سال تحصیلی، نام کاربری انگلیسی و رمز مستقل مدیر کل (حداقل ۱۲ نویسهٔ انگلیسی) را وارد کن. همهٔ پیش‌نیازهای نصب باید سبز باشند. جدول‌ها را خود نصب‌یار می‌سازد؛ **SQL را دستی import نکن**.
8. بعد از پیام موفقیت، با حساب خودت در `admin-login.php` همان سایت وارد شو؛ حساب پیش‌فرضی وجود ندارد. سپس فقط `installer.php` و `config/install-access.php` را از هاست حذف کن. `config/database.php`، `config/installed.lock` و `config/desk-sync-key.php` را حفظ کن؛ از فایل‌ها و دیتابیس یک پشتیبان خصوصی بگیر. از بیرون دوباره بررسی کن `installer.php` دیگر اجرا نمی‌شود و `config/installed.lock`، `sql/install-mysql.json` و `backups/` نه نمایش داده می‌شوند نه دانلود.

## ۳. مدیر افزونه‌ها و کلاس را روی همین سایت نصب کن

1. از بستهٔ اتصالِ بازشده، `baci-plugin-manager-update-v0.1.31.zip` را در **File Manager هاست** در ریشهٔ **همین Baci تازه** (کنار `courses-management.php`) استخراج کن. با وجود نام `update`، هر ده فایل پنل لازم برای نصب اول را دارد. فایل‌های هم‌نام **فقط روی همین نصب تازه و سازگار** جایگزین شوند؛ مسیرهای `includes/` و `plugins/` باید حفظ شوند. بعد از استخراج ZIP را از وب‌ریشه بردار. این ZIP را به فرم «نصب افزونه» نده.
2. با حساب **مدیر کل** در **تنظیمات دیگر ← افزونه‌ها** (`other-settings.php?hub_tab=plugins#hubPanel`) نسخهٔ `0.1.31` را ببین. صفحهٔ **راه‌اندازی یک‌باره** دامنه و دیتابیس را نشان می‌دهد. فقط بعد از تطبیق با **همین محیط تازهٔ آزمایشی**، کادر تأیید را بزن و «راه‌اندازی مدیر افزونه‌ها» را اجرا کن. PHP باید بتواند پوشهٔ خصوصی `.mtagbot-plugins-…` را خارج از مسیر عمومی هاست بسازد؛ اگر میزبان منع کرده، از پشتیبانی بخواه این امکان را بدهد. آن پوشه را داخل `public_html` نبر.
3. در تب افزونه‌ها، از بخش **نصب یا به‌روزرسانی**، فایل `school-classroom-plugin-v0.4.24.zip` را **بدون بازکردن** بارگذاری کن. ZIP بیرونی بستهٔ اتصال، ZIP مدیر یا پوشهٔ استخراج‌شده را اینجا نده. کلاس باید «نصب شد و هنوز غیرفعال است» نشان دهد؛ فعلاً فعال نکن. برای اتصال، توکن ربات یا کلید LiveKit را دستی وارد نکن.

## ۴. نام رسانه را به VPS تازه وصل کن و SSL را خودکار بگیر

در پنل ارائه‌دهندهٔ VPS:

- تصویر **Ubuntu 24.04 LTS، ۶۴ بیتی / amd64** و IPv4 عمومی قابل‌دسترس بگیر. دسترسی SSH/SFTP همان پنل را داشته باش. بهتر است اول snapshot خالی بگیری. این نصب‌گر جایگزین تصویر سیستم‌عامل نیست و روی VPS مشترک، کانتینر یا VPS کلاس قبلی اجرا نمی‌شود.
- در DNS نام رسانه (نمونه `class.example.com`) **یک رکورد A** به IPv4 VPS بزن. برای آن نام **AAAA یا Proxy/CDN/Load Balancer** نگذار؛ در Cloudflare روی **DNS only** باشد. اگر از قبل محدودیت CAA داری، از پشتیبانی DNS بخواه اجازهٔ `letsencrypt.org` برای این نام و اعتبارسنجی TLS-ALPN-01 را بررسی کند. تغییر DNS ممکن است زمان ببرد. IP قدیمی را برای گرفتن گواهی لازم نداری.
- در فایروال پنل **و** فایروال خود Ubuntu اگر فعال است، ورودی **`443/TCP`** (HTTPS و صدور/تمدید)، **`7882/UDP`** (رسانه) و **`7881/TCP`** (رسانهٔ TCP) را به VPS باز کن. دسترسی SSH را دست نزن؛ `80` برای این VPS لازم نیست، `7880` و `7883` را عمومی نکن. DNS خروجی، HTTPS خروجی به Let’s Encrypt و ارتباط HTTPS دوطرفهٔ VPS و هاست مدرسه باید برقرار باشند. ساعت VPS باید درست باشد. نصب‌گر به پنل/DNS یا فایروال دست نمی‌زند.

با FileZilla در حالت **SFTP** (نه FTP)، به IP، کاربر و پورت SSH ارائه‌دهنده وصل شو. در اتصال نخست اثر انگشت SSH را با اطلاعات ارائه‌دهنده بررسی کن. فقط آرشیو `.tar.gz` را به **پوشهٔ خانهٔ همان کاربر SSH** بفرست. فایل گواهی یا کلید خصوصی لازم نیست. در SSH با همان حساب وارد شو:

```bash
cd ~
sha256sum baci-classroom-vps-offline-v1.1.0-ubuntu24.04-amd64.tar.gz
# فقط پس از تطابق هش با فایل انتشار، ادامه بده:
tar -xzf baci-classroom-vps-offline-v1.1.0-ubuntu24.04-amd64.tar.gz
sudo bash baci-classroom-vps-offline/install.sh --tls auto
```

سه پاسخ را بده: **نشانی دقیق HTTPS مدرسه** (با زیرپوشه اگر دارد، بدون `admin-login.php`)، **نام رسانه بدون `https://`**، و **IPv4 عمومی VPS**. همان‌ها را می‌شود غیرتعاملی با `--site`، `--media` و `--ipv4` تعیین کرد. اگر فقط پیش‌بررسی می‌خواهی، به فرمان `--check` اضافه کن: فایل‌ها، DNS و دسترسی به مرجع صدور را می‌سنجد، اما گواهی سفارش نمی‌دهد، چیزی نصب نمی‌کند و باز بودن عمومی پورت ۴۴۳ را ثابت نمی‌کند.

- LiveKit، Caddy، گیرنده و رندرکنندهٔ ضبط، Chromium headless، Python و FFmpeg و وابستگی‌هایشان از **خود آرشیو** نصب می‌شوند؛ دانلود بسته یا Certbot لازم نیست. Caddy از [Let’s Encrypt](https://letsencrypt.org/repository/) با **TLS-ALPN-01 روی TCP 443** گواهی می‌گیرد و آن را نصب می‌کند. هیچ TXT، کلید API دامنه یا انتقال گواهی قدیمی لازم نیست. اینترنت در حالت خودکار برای صدور و تمدید لازم است، نه برای نصب بسته‌های نرم‌افزاری.
- تا زمانی که نام، پورت ۴۴۳ و دسترسی خروجی برقرار باشند، **همین سرویس Caddy گواهی را قبل از انقضا خودکار تمدید می‌کند**. وضعیت و کلیدها در مسیر خصوصی `/var/lib/school-classroom-https` باقی می‌مانند؛ آن را حذف یا منتشر نکن. برای SSL این VPS نه Cron بساز و نه دستی گواهی کپی کن. تمدید SSL سایت PHP همچنان با هاست/AutoSSL آن است.
- صبر کن تا `installation=ok tls=auto` را ببینی. نصب‌گر قبل از این پیام، HTTPS با زنجیره و نام معتبر، API امضاشده و ساخت MP4 آزمایشی را بررسی می‌کند؛ گواهی خودامضا را جایگزین نمی‌کند. سپس مسیر `Baci-VPS-pairing.json` را چاپ می‌کند. اگر نصب موفق است اما فایل خانه موجود بوده یا خروجی ساخته نشده، توضیح [اتصال](#pairing) را ببین؛ نصب دوباره لازم نیست.

## ۵. اتصال خصوصی، فعال‌سازی و Cron

1. با SFTP همان حساب، `Baci-VPS-pairing.json` را از پوشهٔ خانهٔ VPS به رایانهٔ خودت بگیر. آن را بازنشر نکن؛ کلید خصوصی **اتصال رسانه و ضبط** در فایل است، نه گواهی SSL. برای گرفتن نسخهٔ تازه، `sudo baci-vps export` را با همان حساب بزن. اگر نسخه‌ای از قبل در خانه هست، نصب‌گر آن را بازنویسی نمی‌کند؛ اول فایل پیشین را خصوصی جابه‌جا یا حذف کن.
2. در `https://` **همان سایت مدرسه** با مدیر کل، **تنظیمات دیگر ← افزونه‌ها ← کلاس مجازی ← اتصال یک‌مرحله‌ای VPS جدید** را باز کن. JSON را مستقیم در فرم انتخاب کن، کادر تأیید را بزن و ذخیره کن. این فایل را در File Manager هاست، پوشهٔ عمومی، ایمیل یا چت نگذار. بعد از پیام موفق، **فعال‌سازی** را بزن. این کار نیاز به ورود دستی کلید، وب‌هوک یا رمز جداگانهٔ کلاس ندارد.
3. پس از اتصال، نسخه‌های قابل‌انتقال JSON را از رایانه و از پوشهٔ خانهٔ VPS پاک کن یا در پشتیبان رمزگذاری‌شده بگذار. اصل فایل با دسترسی root در `/etc/school-classroom/site-pairing.json` باقی می‌ماند. فایل‌ها و دیتابیس هاست و پوشهٔ خصوصی مدیر را با هم و خارج از وب پشتیبان بگیر.
4. در **cPanel هاست PHP → Cron Jobs**، **Once Per Minute** (هر پنج خانه `*`) را تنظیم کن. فرمان نمونه برای سایت در `public_html/baci`:

   ```sh
   /usr/bin/php /home/CPUSER/public_html/baci/plugins/school-plugins.php classroom-job /baci
   ```

   `CPUSER`، مسیر کامل فایل و مسیر PHP **CLI** همان نسخهٔ هاست را با مقدار واقعی عوض کن؛ از پشتیبانی هاست بپرس یا در Terminal هاست با `php -v` و `command -v php` بررسی کن. آرگومان آخر **زیرمسیر در URL** است، نه مسیر دیسک: اگر نشانی `https://school.example.com` است (حتی اگر docroot روی دیسک نام دیگری دارد)، آن را حذف کن. اگر سایت در ریشهٔ `public_html` است، `/baci` را در مسیر فایل هم بردار. این فرمان را یک بار در Terminal هاست اجرا کن یا خروجی نخستین اجرای Cron را در پنل/ایمیل خصوصی Cron بررسی کن. **Cron روی هاست مدرسه است، نه VPS؛ اجرای HTTP یا URL عمومی جایگزین آن نیست.** برای تحویل باقی صف و کارهای دوره‌ای است؛ به‌تنهایی کلاس باز نمی‌کند.

## ۶. پیش از دعوت دانش‌آموزان، یک کلاس واقعی آزمایشی بگیر

1. از یک دستگاه **بیرون VPS** به `https://نام-رسانه/healthz` برو: بدون اخطار SSL و با پاسخ موفق. در SSH VPS هم بزن:

   ```bash
   sudo baci-vps doctor --online
   ```

   `local=ok`، `tls=auto` همراه `expires=…`، `media_dns=ok` و `school_webhook=ok` را ببین. اگر ضبط را روشن نکرده‌ای، `school_recorder=not_verified_or_disabled` طبیعی است. اگر ضبط فعال است، حدود ۳۰ ثانیه بعد باید `school_recorder=ready` ظاهر شود. `healthz` به‌تنهایی عبور UDP، صدا یا ظرفیت کلاس را ثابت نمی‌کند.
2. نصب پایه فقط مدیر و سال تحصیلی دارد. در Baci یک **کلاس آزمایشی در سال جاری** بساز، یک حساب **دبیر فعال** و یک حساب **دانش‌آموز فعال عضو همان کلاس** اضافه کن. برای آزمون عادی از **مدیریت دروس ← کلاس‌ها و دروس ← برنامه هفتگی و دبیران** یک درس/زنگ برای همان دبیر و کلاس ثبت کن. آزمون را در همان زمان به وقت تهران انجام بده. اگر فقط آزمون بی‌اعلان می‌خواهی، به‌جایش در تنظیمات افزونه برای **یک جمعه** «آزمایش ۲۴ ساعتهٔ جمعه» و گزینهٔ «اجازهٔ ورود آزمایشی به دانش‌آموزان همان کلاس» را فعال کن؛ این تمرین گزارش رسمی یا ضبط ندارد.
3. از دو دستگاه و دو حساب جدا (ترجیحاً یکی روی اینترنت دیگر) وارد کاشی **کلاس مجازی** شو. دانش‌آموز باید تا اتصال دبیر منتظر بماند. اجازهٔ میکروفون را در مرورگر بده و دبیر برای دانش‌آموز اجازهٔ صحبت بدهد؛ در هر دو جهت صدا را بشنو. یک خط روی تخته بکش و در دستگاه دوم ببین. حداقل یک دقیقه حضور را بررسی کن، بعد دبیر **بستن کلاس برای همه** (در جمعه، **بستن اتاق آزمایشی برای همه**) را بزند؛ فقط بستن صفحه کافی نیست. برای زنگ عادی، گزارش حضور را در پنل بررسی کن. اگر رسانه فقط روی یک شبکه کار کرد، به‌ویژه `7882/UDP` و `7881/TCP` را با ارائه‌دهنده بررسی کن.
4. **ضبط و اعلان اختیاری‌اند.** برای اولین تست خاموش بمانند. اگر بعداً نیاز شد، تنظیم مقصد خصوصیِ مجاز را در خود سایت انجام بده، فقط روی یک زنگ معمولی با رضایت افراد و مقصد آزمایشی ضبط را روشن کن، و هنگام بستن زنگ ساخت/ارسال را تأیید کن. دریافت ضربان Recorder یا `healthz` موفق، تحویل به پیام‌رسان را ثابت نمی‌کند.

<a id="files-tls"></a>
## اگر VPS برای صدور گواهی اینترنت ندارد: حالت آفلاین واقعی

مراحل سایت و اتصال همان است. فقط برای نصب VPS به جای `--tls auto` از `--tls files` استفاده کن. از مرجع صدور یا پشتیبانی خود، **گواهی عمومی برای نام جدید رسانه**، زنجیرهٔ کامل `fullchain.pem` و کلید متناظر `privkey.pem` (بدون عبارت رمز) را از مسیر خصوصی بگیر. کلید را در چت نگذار. دو فایل معمولی، **نه symlink**، را در پوشهٔ خانه کنار آرشیو بگذار؛ نه داخل پوشهٔ استخراج‌شده. پس از کنترل هش و استخراج:

```bash
cd ~
chmod 600 privkey.pem
sudo bash baci-classroom-vps-offline/install.sh --tls files
```

اگر اسم یا مسیر فرق دارد `--cert /مسیر/fullchain.pem --key /مسیر/privkey.pem` بده. در این حالت نه صدور و نه تمدید ACME انجام نمی‌شود؛ قبل از انقضا با پشتیبانی برای تعویض گواهی هماهنگ کن و تاریخ را با `sudo baci-vps doctor` ببین. برای تعویض، نصب‌گر تازه را روی VPS زنده اجرا نکن. گواهی خودامضا، گواهی فقط CDN یا نادیده گرفتن اخطار HTTPS قابل قبول نیست. پس از نصب، کارکرد کلاس و ارتباط هاست همچنان به شبکه نیاز دارند.

## اگر خطا دیدی

| پیام یا نشانه | کار بعدی |
|---|---|
| `Media DNS is not ready` | نام و IPv4 را تطبیق بده، `A` مستقیم بگذار، `AAAA`/Proxy را برای رسانه بردار و منتظر انتشار DNS بمان. `--check` فقط دیدِ resolver خود VPS را بررسی می‌کند. |
| `Cannot reach the trusted Let’s Encrypt…` | ساعت، DNS و خروجی HTTPS VPS را با پشتیبانی بررسی کن. اگر خروجی فراهم نیست، حالت آفلاین با گواهی آماده را انتخاب کن. |
| `Automatic TLS did not obtain…` | ورودی عمومی `443/TCP`، نبودن Proxy/CDN، CAA و دسترسی Let’s Encrypt را بررسی کن. برای دیدن علت روی **خود VPS** `sudo journalctl -u school-classroom-https.service -n 50 --no-pager` را بزن؛ `timeout`، `unauthorized` یا `rateLimited` راهنماست. پشت سر هم نصب را تکرار نکن؛ محدودیت صدور ممکن است اعمال شود. |
| `Integrity` یا `Existing …` | هش را بررسی و در پوشه‌ای خالی دوباره استخراج کن؛ هیچ فایل اضافی داخل آن نگذار. اگر مسیر، واحد یا پورت از قبل استفاده می‌شود، نصب‌گر آن را بازنویسی/خاموش نمی‌کند. به VPS تازه برگرد. |
| `Offline APT` یا خطای راه‌اندازی | اگر apt دیگری مشغول است صبر کن. downgrade، حذف بستهٔ سیستم یا فعال کردن دانلود راه‌حل نیست. نصب نیمه‌تمام در خطای عادی به‌جز پیش‌نیازهای Ubuntu برگردانده می‌شود؛ در قطع برق/`kill -9` از snapshot خالی استفاده کن، نه حذف دستی مسیرها. |
| تب افزونه‌ها، آپلود یا اتصال کار نمی‌کند | نصب روی همان ریشهٔ Baci، نسخهٔ `0.1.31`، نقش مدیر کل، افزونه‌های PHP، محدودیت آپلود و پوشهٔ خصوصی را بررسی کن. اگر JSON رد شد، نشانی دقیق سایت و زیرپوشه یا غیرفعال بودن کلاس را بررسی کن. |
| `school_webhook=not_verified` | سایت HTTPS را از VPS قابل‌دسترسی کن؛ تطابق نشانی، فعال‌سازی و عبور هدر `Authorization` تا PHP را با هاست بررسی کن. روی درگاه وب‌هوک نباید تغییر مسیر، کپچا یا صفحهٔ ورود میزبان باشد. |

اجرای دوباره روی VPS که نصبش موفق شده **فقط وضعیت را می‌خواند**؛ دامنه، گواهی و کلیدها را عوض نمی‌کند. نصب‌گر به‌روزرسانی خودکار نرم‌افزار نیست. برای گزارش مشکل، نام مرحله و کد خطا کافی است؛ فایل اتصال، کلید، ویدیو یا لاگ خصوصی نفرست.

<a id="existing"></a>
## انتقال نصب موجود، نه نصب از صفر

بستهٔ پایهٔ Baci، دیتابیس خالی و این نصب‌گر را روی سایت/VPS موجود اجرا نکن. برای جایگزینی VPS، یک VPS تازه و ترجیحاً **نام رسانهٔ تازه** آماده کن. اگر نام قدیمی را نگه می‌داری، در حالت `auto` صدور تا وقتی DNS و ۴۴۳ به VPS جدید نرسند انجام نمی‌شود؛ تغییر را در زمان نگهداری برنامه‌ریزی کن. با `files` و گواهی معتبر همان نام می‌توان پیش از تغییر DNS نصب محلی کرد.

برای سایت موجود اول پشتیبان خصوصی فایل‌ها، پایگاه و پوشهٔ مدیر بگیر. اگر مدیر استاندارد `0.1.30` و تب سالم افزونه‌ها را داری، فقط `plugins/school-plugins.php` از ZIP مدیر `0.1.31` عوض شده است. اگر کلاس `0.4.24` را داری دوباره نصبش نکن. برای نسخهٔ قدیمی‌تر یا پنل سفارشی، [راهنمای ارتقای مستقل](https://github.com/Maxess/bacirat-function/blob/0b6d47fc8a5b1b23fe48670395049a2b429dfb3c/plugin-manager/README-fa.md) و مقایسه با پشتیبان را ملاک قرار بده. پس از پایان زنگ‌ها، رسیدن فیلم‌ها و تخلیهٔ صف اعلان، **آماده‌سازی ارتقا (حفظ داده و کنترل صف)** را بزن؛ نه «غیرفعال‌سازی عادی» و نه «حذف کامل». سپس فایل اتصال را وارد کن، بعد از آماده بودن HTTPS رسانه فعال کن و آزمون دو دستگاه را انجام بده. اگر صف/زنگ حل‌نشده از VPS ازکارافتاده مانده، تغییر اتصال عمداً مسدود می‌شود؛ جدول و صف را دستی پاک نکن. این نصب‌گر داده یا فیلم قبلی را منتقل نمی‌کند. VPS قبلی و پشتیبان را تا پایان آزمون نگه دار.
