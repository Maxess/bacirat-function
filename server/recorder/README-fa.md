# ضبط کلاس Baci · Recorder 0.4.21

## ارتقا از Recorder 0.4.18 یا 0.4.20 در حال کار

برای ثبت لیزر و کنترل تصویر اصلی فیلم، افزونهٔ کلاس `0.4.21` را روی سایت و Recorder `0.4.21` را روی همان VPS ضبط نصب کن. ضبط‌کنندهٔ قدیمی با سایت جدید همچنان کار می‌کند، اما دکمه‌های چیدمان ظاهر نمی‌شوند. اگر فقط ضبط‌کننده را ارتقا بدهی، سایت قدیمی اطلاعات لیزر، دبیر و انتخاب‌های چیدمان را نمی‌فرستد. هیچ فیلمی که قبلاً ضبط شده عوض نمی‌شود.

پس از اتمام زنگ‌ها، ضبط، پردازش و ارسال، `upgrade-v0.4.21.sh` و `baci-classroom-recorder-v0.4.21.zip` را از بستهٔ ارتقا کنار هم در پوشهٔ خصوصی **VPS ضبط** بگذار. پس از بررسی هش‌ها و اسکریپت:

```sh
version=0.4.21
sudo bash "./upgrade-v${version}.sh" "./baci-classroom-recorder-v${version}.zip"
```

این اسکریپت مستقیماً نصب استاندارد و فعال `0.4.18` یا `0.4.20` را ارتقا می‌دهد. برای `0.4.16` و `0.4.17` ابتدا [ارتقای `0.4.18`](upgrade-v0.4.18.sh) را انجام بده. اسکریپت تعمیر نصب نیست؛ مرورگر، AppArmor، LiveKit، تنظیمات، انبار خصوصی یا کلیدها تغییر نمی‌کنند. اگر راه‌اندازی تأیید نشود، فایل‌های قبلی برنامه برمی‌گردند.

### نمای فیلم

- اگر دوربین دبیر همان زنگ روشن باشد، تصویر اصلی دوربین است. اگر دوربین روشن نباشد، صفحهٔ مشترک تصویر اصلی است. اگر هیچ‌کدام روشن نباشند، تخته تصویر اصلی است.
- وقتی هر دو تصویر روشن‌اند، ارائه‌دهندهٔ مجاز می‌تواند بالای **صفحهٔ مشترک** «نمایش در ضبط» را بزند تا آن صفحه تصویر اصلی و دوربین دبیر یک وب‌کم در نوار پایین شود. انتخاب به همان انتشار صفحه مربوط است؛ اشتراک جدید باید جداگانه انتخاب شود.
- دکمهٔ جداگانهٔ **نمایش در ضبط** بالای تخته، آن را کنار تصویر اصلی می‌آورد؛ برای برگشت دوباره همان دکمه را بزن. انتخاب‌ها فقط قاب MP4 را عوض می‌کنند و با اتاق/ضبط جدید از نو آغاز می‌شوند.
- در نوار پایین فقط وب‌کم‌های قابل پخش می‌آیند. دوربینی که تصویر اصلی است تکرار نمی‌شود. اگر موردی برای نوار نماند، جای آن به تصویر اصلی می‌رسد. تصویرها کشیده یا بریده نمی‌شوند.
- لیزر با همان محدودهٔ زوم و پیمایش روی تخته در MP4 ثبت می‌شود و محو می‌شود؛ بخشی از نوشته‌ها نیست. PDF از قلم وزیرمتن کلاس زنده برای فونت تعبیه‌نشده استفاده می‌کند و فقط صفحهٔ فعال رسم می‌شود. عنوان نام مدرسه، کلاس مجازی، نام همان درس و عبارت `طراحی و توسعه : س. مهدی بیات` حفظ شده‌اند. صدای کلاس از میکروفون‌های باز می‌آید و به انتخاب نمای فیلم وابسته نیست.

## نصب نخستین بار

این بسته فقط روی **VPS اختصاصی رسانهٔ سایت آزمایشی** نصب می‌شود؛ نه در File Manager و نه در پوشهٔ وب. سرویس جدا به LiveKit موجود روی `127.0.0.1:7880` وصل می‌شود و با HTTPS کار را از سایت می‌گیرد. Redis/Docker، پورت عمومی جدید، تنظیم Caddy، وب‌هوک LiveKit یا وب‌هوک ربات‌ها را تغییر نده. روی VPS ضعیفِ فقط‌صوت بدون سنجش روشن نکن: برای آزمون یک ضبط هم‌زمان با کلاس ۴ نفره، از ۴ vCPU، ۴ GiB RAM و دست‌کم ۳ GiB فضای آزاد خصوصی شروع کن. این ظرفیتِ تضمین‌شده نیست.

## ۱. سایت

۱. پس از پایان زنگ‌ها و بکاپ، سایت آزمایشی Baci V1.15 را با روش حفظ داده به مدیر `0.1.27` و کلاس `0.4.21` ارتقا بده. ضبط پیش‌فرض **خاموش** است و ارتقای معمول نیازی به این VPS ندارد.
۲. یک کلید تازهٔ اختصاصی با `openssl rand -hex 32` **روی دستگاه خودت** بساز. آن را با کسی به اشتراک نگذار. در تنظیمات کلاسِ غیرفعال با حفظ داده، «ضبط اختیاری کلاس با سرویس جداگانهٔ VPS» و «کلید مستقل سرویس ضبط» را ثبت کن و افزونه را فعال کن. کلیدهای LiveKit یا ربات‌ها را جایگزین نکن.
۳. مدیر کل، **تنظیمات دیگر ← افزونه‌ها ← کلاس مجازی ← گروه‌های پیام‌رسان و ضبط کلاس**. برای هر کلاسِ سال جاری یک گروه دلخواه ثبت کن. گروه‌های بله، روبیکا و تلگرام از گفت‌وگوهای ربات‌های همین سایت می‌آیند؛ ربات لازم نیست مدیر باشد، اما باید عضو باشد و پیام‌رسان باید ارسال ویدیو به آن گروه را مجاز بداند. برای گروهی که در فهرست نیست، در گروه ربات را خطاب کن یا در «گفتگوهای ربات» آن را ثبت/تازه کن. API ربات‌ها فهرست همهٔ گروه‌های عضو را نمی‌دهد. در بله و روبیکا، `getChat` نوع و شناسه را می‌سنجد؛ API به‌ترتیب بررسی نقش غیرمدیر را تضمین نمی‌کند یا متد نقش ندارد. در نهایت خود پیام‌رسان اجازهٔ ارسال را اعمال می‌کند. مسیر گروه‌های فیلم، جدا از اعلان خصوصی حضور است.

## ۲. VPS: نصب جدا و خصوصی

نمونه برای Ubuntu 24.04. ZIP مخصوص Recorder را پس از بررسی `SHA256SUMS.txt` در پوشهٔ موقت غیرعمومی باز کن. فرمان‌های نصب را فقط پس از بازبینی در همان پوشه اجرا کن:

```sh
sudo apt update
sudo apt install python3-venv ffmpeg unzip ca-certificates fonts-noto-core
sudo useradd --system --user-group --no-create-home --home-dir /var/lib/school-classroom-recorder --shell /usr/sbin/nologin school-recorder
sudo install -d -m 0755 /opt/school-classroom-recorder
sudo install -m 0644 ./*.py ./*.html ./*.css ./*.js ./*.zip ./*.txt /opt/school-classroom-recorder/
sudo install -d -m 0755 /opt/school-classroom-recorder/fonts
sudo install -m 0644 fonts/* /opt/school-classroom-recorder/fonts/
sudo python3 -m venv /opt/school-classroom-recorder/venv
sudo /opt/school-classroom-recorder/venv/bin/pip install -r /opt/school-classroom-recorder/requirements.txt
sudo env PLAYWRIGHT_BROWSERS_PATH=/opt/school-classroom-recorder/browsers \
  /opt/school-classroom-recorder/venv/bin/playwright install --with-deps --only-shell chromium
```

اگر کاربر سرویس از قبل موجود است دوباره نساز. هیچ‌کدام از پوشه‌ها یا فایل‌های کد نباید برای کاربر سرویس قابل نوشتن باشند. مرورگر با sandbox فعال اجرا می‌شود. روی Ubuntu 24.04 اگر AppArmor برای **همین** `chrome-headless-shell` خطای user namespace داد، از مدیر VPS بخواه فقط فایل اجرایی Playwright در مسیر root-owned نصب را با یک پروفایل محدودِ `userns` مجاز کند؛ `--no-sandbox` نگذار و تنظیم سراسری AppArmor را خاموش نکن. در سرور محدود به دانلود، وابستگی‌ها را از منابع رسمی روی دستگاه قابل‌اعتماد دانلود و سپس منتقل کن.

فایل `/etc/school-classroom-recorder.json` را با مجوز `0600` و مالک `root` در ویرایشگر خود VPS بساز. `site` نشانی HTTPS **سایت تست**، با زیرمسیر احتمالی و بدون اسلش انتهایی است. `secret` همان کلید مستقل بالا است. این فایل را در وب، ZIP یا مخزن نگذار:

```json
{"site":"https://school-test.example.ir","secret":"کلید_خصوصی_مستقل_ضبط"}
```

```sh
sudo install -m 0644 school-classroom-recorder.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now school-classroom-recorder.service
sudo systemctl status school-classroom-recorder.service
```

VPS باید به سایت، API پیام‌رسان و سرورهای بارگذاری روبیکا دسترسی خروجی HTTPS داشته باشد. اگر تلگرام از واسط استفاده می‌کند، همان واسط HTTPS ثبت‌شدهٔ مدرسه باید قابل‌اعتماد باشد و از VPS هم در دسترس باشد. هاست مدرسه نیز باید `getChat` (و برای تلگرام `getMe` و `getChatMember`) را بتواند فراخوانی کند و هدر `Authorization` را به PHP بدهد. هر بار ارسالِ مجاز، اطلاعات ربات فقط در حافظهٔ سرویس اختصاصی VPS استفاده می‌شود؛ توکن ربات تازه لازم نیست. **آماده** در پنل یعنی مرورگر/انکودر بالا آمده و آخرین تماس سالم است، نه اینکه آزمون واقعی رسانه یا پیام‌رسان انجام شده باشد.

## ۳. آزمونِ بدون اطلاعات واقعی دانش‌آموز

- برای آزمایش گروهی را انتخاب کن که دانش‌آموز واقعی ندارد. در یک زنگ کنترل‌شده، با دبیر یا مدیر مجاز و یک حساب آزمایشی دانش‌آموز وارد شو. از منوی کلاس، زیر نوشتن روی تخته و بالای تنظیمات، **ضبط کلاس ← شروع ضبط**. نشان ضبط باید برای هر دو دیده شود. یک PDF آزمایشی را باز کن، صفحه را عوض کن، مثلاً در ۲۰۰٪ تخته را بپیمای و روی همان قسمت بنویس. ببین دانش‌آموز همان بخش را می‌بیند و بدون اجازه امکان نوشتن ندارد. با وبکم، اشتراک صفحه و میکروفون آزمایشی ضبط را کامل کن. مرورگر دبیر مجری ضبط نیست؛ تا وقتی یک مسئول مجاز کلاس را زنده نگه می‌دارد، خروج دبیر ضبط را متوقف نمی‌کند. اگر طبق روال فعلی کلاس بدون مسئول بماند و به حالت انتظار برود، ضبط موقتاً متوقف می‌شود و با ادامهٔ همان زنگ در اتاق جدید از سر گرفته می‌شود.
- **بستن کلاس برای همه ← خیر**: هیچ ویدیویی نباید برسد. در زنگ دیگر **بله** را بزن؛ در همان گروهِ نمایش‌داده‌شده صدای هر دو حسابِ آزمایشی را بازپخش کن و با خاموش کردن آخرین وب‌کمِ فرعی، باز شدن فضای فیلم را ببین. هر دو دکمهٔ «نمایش در ضبط»، تغییر تصویر اصلی و محوشدن لیزر روی تختهٔ زوم‌شده را در MP4 بررسی کن. نام مدرسه، نام همان درس و نشان توسعه را در خود فیلم ببین و پیوستگی حروف PDF را با تختهٔ زنده مقایسه کن. چت، نام افراد و فهرست حاضرانِ برنامه داخل قاب ضبط نیستند. اشتراک صفحه ممکن است هر چیزی را که کاربر به‌اشتراک می‌گذارد نشان دهد؛ دربارهٔ ضبط و مقصد به کلاس اطلاع بده و فقط گروه مورد تأیید مدرسه را انتخاب کن.
- با تغییر گروه یا خروج ربات قبل از ارسال، نباید فیلم به گروه تازه برود. در پنل، پس از تأیید همهٔ بخش‌ها، پیام پاک‌شدن فایل VPS را بررسی کن. بستن خودکار بدون تأیید ارسال نمی‌کند. ضرب‌العجل زنگ و مجوزهای رسانه تغییر نکرده‌اند.

## بررسی پاک‌شدن و نگهداری

پس از ارسال موفق تمام بخش‌ها و قبل از شروع ضبط بعدی، در «گروه‌های پیام‌رسان و ضبط کلاس» وضعیت پاک‌سازی را ببین. روی VPS می‌توانی فقط تعداد MP4 باقی‌مانده در فضای اختصاصی ضبط را بشماری؛ اگر این تنها کار بوده، نتیجه باید صفر باشد. فایل‌های کار فعال یا ناموفق را صرفاً با دیدن عدد غیرصفر پاک نکن.

```sh
sudo find /var/lib/school-classroom-recorder -type f -name '*.mp4' -printf '.' | wc -c
```

- ضبط روی VPS به‌صورت MP4 با H.264/AAC بهینه می‌شود (`1280×720`، `12 fps`، صدای AAC تک‌کاناله)؛ پس از بستن، آخرین بخش آماده و ارسال آغاز می‌شود. پایلوت برای زنگ‌های حداکثر دو ساعته است. هر بخش حداکثر حدود ۷ دقیقه و ۳۰ ثانیه و ۴۵٬۰۰۰٬۰۰۰ بایت است؛ کوتاه‌تر شدن بخش‌ها برای حفظ کیفیت زیر سقف حجم پیام‌رسان است. طول فیلم/شبکه بر زمان دریافت اثر دارد. پایلوت در زمان ضبط، پردازش و ارسال تنها یک کار می‌پذیرد.
- ویدیو فقط در `/var/lib/school-classroom-recorder` با مجوز خصوصی قرار می‌گیرد؛ این مسیر را به وب، بکاپ عمومی یا اشتراک فایل وصل نکن. با دریافت و ثبت رسید معتبر پیام‌رسان، **فایل همان بخش بلافاصله از VPS حذف می‌شود**، حتی اگر سایت موقتاً قطع باشد. پس از تأیید آخرین بخش، فایل‌های موقت همان ضبط هم حذف می‌شوند؛ فقط رسید محلی کوچک تا ثبت وضعیت در سایت می‌ماند. این حذف، پیام و فیلم داخل گروه را دست نمی‌زند. رد قطعی یا نتیجهٔ نامشخص به گروه دیگر ارسال نمی‌شود؛ پس از پاسخِ مبهم دوباره تلاش خودکارِ ارسال انجام نمی‌شود. برای نتیجهٔ نامشخص ابتدا خود گروه را بررسی کن. فیلمِ ناموفق حداکثر تا ۲۴ ساعت پس از موعد زنگ (پاک‌سازی دوره‌ای محلی) نگه‌داری و سپس حذف می‌شود؛ اگر کل VPS خاموش باشد پاک‌سازی با بالا آمدن سرویس انجام خواهد شد. `worker.json` را هنگام ارتقا نگه دار؛ کلید یا توکن در `worker.json` ذخیره نمی‌شود.
- پیش از خاموش‌کردن یا به‌روزرسانی سرویس، بگذار ضبط و ارسال تمام و نتیجه ثبت شود. برای خاموش‌کردن: `sudo systemctl disable --now school-classroom-recorder.service`؛ در سایت هم پس از پایان زنگ‌ها ضبط را در حالت «غیرفعال‌سازی (حفظ داده)» خاموش کن و کلاس را دوباره فعال کن. فایل‌های موقت سرویسِ متوقف‌شده خودبه‌خود حذف نمی‌شوند؛ مدیر سرور پوشهٔ خصوصی اختصاصی ضبط را بررسی و فیلم‌های باقی‌مانده را طبق سیاست مدرسه پاک کند. سرویس LiveKit و وب‌هوک‌ها دست‌نخورده می‌مانند.
