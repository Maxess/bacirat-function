# رسانه و ناظر کلاس مجازی روی VPS Ubuntu 24.04

این مسیر مستقل از PersianMeet است. سایت PHP روی هاست اشتراکی می‌ماند؛ مرورگر سیگنال‌دهی را از Caddy با HTTPS/WSS و صدا را مستقیم با LiveKit انجام می‌دهد. سقف اولیهٔ پایلوت ۴ اتصال صوتی در هر اتاق است. Redis، Docker، TURN و ضبط در این پروفایل استفاده نمی‌شوند.

اگر موتور صوتی پایلوت برای همین سایت تست از قبل فعال است، مراحل ۱ تا ۳ نصب تازه را تکرار نکن. فقط آخرین فایل‌های پوشهٔ `server/` را بگیر و به [مرحلهٔ ناظر](#supervision) برو.

## ۱. دریافت فقط فایل‌های نصب از شاخهٔ آزمایش

روی VPS با SSH وارد شو. ابتدا Ubuntu را به‌روز نگه دار و اگر `git`، `curl`، Python 3 یا گواهی‌های ریشه موجود نیستند آن‌ها را نصب کن:

```bash
sudo apt update
sudo apt install git curl python3 ca-certificates
```

نسخهٔ نصب‌گر فقط از شاخهٔ کاری همین مخزن گرفته می‌شود. دریافت sparse از دانلود بستهٔ قدیمی PersianMeet جلوگیری می‌کند (درصورتی‌که سرویس Git قابلیت partial clone داشته باشد):

```bash
git clone --depth 1 --filter=blob:none --sparse --single-branch \
  --branch arena/a1a6c00e-bacirat-function \
  https://github.com/Maxess/bacirat-function.git school-media-pilot
git -C school-media-pilot sparse-checkout set server
cd school-media-pilot
```

## ۲. آماده‌سازی، بدون استارت یا تغییر فایروال

- `media.example.ir` در نمونه باید زیردامنهٔ اختصاصی VPS باشد و رکورد `A` به IPv4 عمومی سرور اشاره کند. دامنهٔ PHP هاست اشتراکی جداست. از پراکسی/CDN برای این زیردامنه در پایلوت استفاده نکن. `AAAA` را تنها وقتی بگذار که مسیر IPv6 و TLS را هم آزموده‌ای؛ رسانهٔ پایلوت با IPv4 تنظیم می‌شود.
- `X.X.X.X` را به IPv4 عمومی واقعی VPS و `https://test-school.example.ir` را به مبدأ دقیق **سایت تست** عوض کن. این مقادیر را در خود سرور وارد کن؛ نیازی به فرستادن آن‌ها در چت نیست.

```bash
sudo /usr/bin/python3 -I server/install.py media.example.ir X.X.X.X https://test-school.example.ir
```

نصب‌گر فایل رسمی Linux amd64 نسخهٔ `1.13.11` را دانلود و SHA-256 ثبت‌شده در GitHub را بررسی می‌کند. اگر دانلود دارایی GitHub روی VPS در دسترس نبود، همان [آرشیو رسمی LiveKit](https://github.com/livekit/livekit/releases/download/v1.13.11/livekit_1.13.11_linux_amd64.tar.gz) را از دستگاهی که دسترسی دارد منتقل کن و `--archive /path/to/livekit_1.13.11_linux_amd64.tar.gz` را به همان دستور اضافه کن؛ چک یکسان است. هیچ‌یک از فایل‌های پیکربندی موجود را جایگزین نمی‌کند و به SSH، apt، فایروال یا Caddy دست نمی‌زند. خروجی موفق `media_prepared=yes` است. اگر نصب قبلی وجود دارد، قبل از هر تغییر از پیکربندیِ خصوصی بکاپ بگیر؛ نصب‌گر از بازنویسی جلوگیری می‌کند.

## ۳. مسیر شبکه و HTTPS

| پورت | کاربرد |
| --- | --- |
| `443/TCP` | صفحهٔ PHP از طریق این آدرس WSS ویجت را وصل می‌کند و بک‌اند هاست آزمایشی هم فقط همین پورت را برای API می‌خواهد. |
| `80/TCP` | مسیر HTTP-01 وقتی Caddy گواهی از اینترنت می‌گیرد؛ دسترسی مرجع صدور لازم است. |
| `7882/UDP` | رسانهٔ WebRTC، یک پورت به‌جای یک بازه. در فایروال پنل و VPS برای شبکه‌های پایلوت مجاز شود. |
| `7881/TCP` | ICE/TCP اختیاری، اگر برای شبکهٔ آزمون لازم شد. این پورت HTTPS نیست. |
| `7880/TCP` و `7883/TCP` | داخلی و روی loopback؛ **در فایروال عمومی باز نشوند**. |

اگر پنل امکان محدودسازی دارد، مسیر رسانه را اول فقط برای شبکه‌های پایلوت باز کن. قواعد SSH یا سرویس‌های دیگر را تغییر نده. SSL سایت مدرسه جای گواهی معتبر سیگنال‌دهی روی زیردامنهٔ رسانه را نمی‌گیرد.

اگر Caddy روی VPS موجود نیست و وب‌سرور دیگری روی ۸۰/۴۴۳ فعال نیست، `sudo apt install caddy` بزن. اگر وب‌سرور دیگری داری، آن را بدون طرح جایگزین نکن. در Caddy موجود، ابتدا از `/etc/caddy/Caddyfile` بکاپ بگیر و این **یک خط** را با `sudoedit /etc/caddy/Caddyfile` در سطح اصلی اضافه کن؛ کل فایل را جایگزین نکن و از تکرار بلاک زیردامنه خودداری کن:

```caddyfile
import /etc/school-classroom/Caddyfile
```

سپس:

```bash
sudo caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
sudo systemctl start school-classroom-admission school-classroom-sfu
sudo systemctl reload caddy
```

اگر گواهی صادر نشد، DNS و دسترسی بیرونی ۸۰/۴۴۳ را بررسی کن. اعتبارسنجی TLS را غیرفعال نکن. DNS-01 در صورت محدودیت ورودی HTTP مسیر دیگری است ولی نیاز به راه‌اندازی جداگانهٔ ارائه‌دهندهٔ DNS دارد؛ این نصب‌گر آن را خودکار نمی‌کند.

روی VPS وضعیت را بدون لاگ خصوصی گزارش کن:

```bash
sudo systemctl show school-classroom-sfu school-classroom-admission -p Id -p ActiveState -p Result
curl -fsS --max-time 8 https://media.example.ir/healthz
```

در صورت امکان `healthz` را از بیرون VPS هم امتحان کن. پاسخ سالم ۲۰۰ از مسیر HTTPS نشانهٔ دسترسی تا HTTP موتور است، **نه** اثبات کارکرد UDP و کیفیت صدا. اگر هر دو سرویس در پایلوت پایدار بودند می‌توانی `sudo systemctl enable school-classroom-admission school-classroom-sfu` بزنی. برای توقف پایلوت هر دو را متوقف و `import` همان سایت آزمایشی را از Caddy بردار؛ فایل کلیدها و دیتابیس اصلی مدرسه به هم وابسته نیستند.

## ۴. آماده‌سازی ناظر نسخهٔ ۰٫۳٫۰، روی VPS موجود یا تازه

کلاس‌های نسخهٔ ۰٫۳٫۰ علاوه بر دو سرویس قبلی به **`school-classroom-watch`** نیاز دارند. ابتدا مدیر و ZIP کلاس را طبق [راهنمای هاست](../plugin-manager/README-fa.md) نصب کن. در صفحهٔ مدیریت مدرسه پیشوند `test-…` را برای همین نصب بردار. کلیدهای قبلی رسانه برای همان دامنه معتبرند؛ آن‌ها را در دستور زیر یا در چت قرار نده.

- این مرحله برای VPS‌ **اختصاصی آزمون همین سایت** است. پیش از شروع زنگ‌ها و در زمان بیکاری سرویس انجام بده. فایل پیشین `admission.py` در `/etc/school-classroom/admission-pilot.py.bak` خصوصی نگه‌داری می‌شود. اگر درگاه پایلوت سفارشی شده باشد، نصب‌گر آن را بازنویسی نمی‌کند.
- اگر قبلاً از این مخزن clone کرده‌ای، روی شاخهٔ آزمایشِ پوشهٔ نصب `git pull --ff-only` بزن. `test-0123456789abcdef0123` فقط نمونه است. اگر سایت در ریشهٔ دامنه است، `--site-path /school-test` را حذف کن؛ در غیر این صورت زیرمسیر واقعی بدون اسلش انتهایی را بده. دامنهٔ HTTPS از `admission.json` موجود خوانده می‌شود.

```bash
sudo /usr/bin/python3 -I server/install.py supervise test-0123456789abcdef0123 --site-path /school-test
sudo systemctl restart school-classroom-admission
sudo systemctl enable --now school-classroom-watch
sudo systemctl show school-classroom-watch -p ActiveState -p Result
```

فرمان اول فقط فایل‌های ناظر و درگاه ورود را آماده می‌کند و `daemon-reload` می‌زند. باینری و پیکربندی LiveKit، کلیدها، Caddy، فایروال، SSH و PersianMeet تغییر نمی‌کنند. درگاه خودش همچنان روی `127.0.0.1:7883` است و ناظر پورت جدیدی باز نمی‌کند. شرط لازم دسترسی **خروجی VPS به HTTPS سایت تست**، دسترسی فعلی هاست به HTTPS رسانه، و ساعت درست هر دو سرور است. کلاس را در پنل فعال کن و منتظر پیام آماده‌شدن ناظر بمان؛ `systemctl` به تنهایی سلامت نمونه‌برداری را ثابت نمی‌کند.

اگر ناظر آماده نشد، مسیر سایت، پیشوند، گواهی TLS و فعال‌بودن افزونه و سرویس‌های رسانه و درگاه را بررسی کن. پیام‌های خلاصهٔ خصوصی را روی VPS با `sudo journalctl -u school-classroom-watch -n 15 --no-pager` ببین. کلید، نشست، توکن، فایل تنظیم یا هویت حاضران را از سرور خارج نکن.

برای توقف ناظر بدون تغییر سرویس پایلوت: `sudo systemctl disable --now school-classroom-watch`. این کار فقط اتاق‌های زمان‌بندی‌شدهٔ همین پیشوند را می‌بندد. اگر افزونه پس از حذف دوباره نصب شد، قبل از راه‌اندازی ناظر پیشوند جدید و زیرمسیر را در `/etc/school-classroom/watch.env` با `sudoedit` و پس از پشتیبان‌گیری جایگزین کن. دو ناظر با یک پیشوند اجرا نکن.

## ازکارافتادن و بازگشت کلاس

ناظر تقریباً هر سه ثانیه فهرست و وضعیت رسانه را می‌گیرد. شرط فعال‌بودن زنگ، شناسهٔ اتصال رسانهٔ فعال **و** دریافت ضربان معتبر همان نشست از دبیر یا مسئول مجاز است. نمونهٔ کهنه مجوز ورود تازه و دسترسی چت/تخته نمی‌دهد. با از دست‌رفتن آخرین ناظرِ یک کلاس، سرویس اتاق همان زنگ را روی LiveKit می‌بندد؛ اگر ناظر دیگری هنوز در اتاق است، کلاس ادامه دارد. دانش‌آموز در انتظار می‌ماند تا زنگ با اتاق تازه از سر گرفته شود. شمارش از بازه‌های تأییدشده انجام می‌شود؛ قطع ارتباط به معنای ثبت ثانیه‌های بدون نمونه نیست.

در قطع سایت/درگاه، مجوز ورود تازه پس از انقضای نمونه بسته می‌شود و ناظر حذف اتاق‌های تحت مالکیت خود را از API داخلی پیگیری می‌کند. برای خروج ناگهانی یا توقف خودِ ناظر، `ExecStopPost` تلاش می‌کند همان اتاق‌ها را پاک کند، و watchdog روند گیرکرده را دوباره راه می‌اندازد. راه‌اندازی ناظر ابتدا اتاق‌های زمان‌بندی‌شدهٔ قدیمی همین نصب را می‌بندد. اگر API داخلی موتور هیچ پاسخ نمی‌دهد، بستن رسانه را نمی‌توان تأیید کرد؛ برای توقف قطعی در **VPS اختصاصی تست**، در صورت نیاز `sudo systemctl stop school-classroom-sfu` را اجرا کن. توقف آن کل رسانهٔ این سرویس را قطع می‌کند، نه صرفاً یک زنگ. قطع‌و‌وصل اینترنت، رفتار SFU و تأخیر درخواست‌ها حد سخت تضمین‌شده برای زمان قطع نمی‌دهند.

## آزمون عملکردی بعد از نصب در سایت تست

1. دانش‌آموز، دبیر همان کلاس، ناظر مجاز و حساب کلاس دیگر را در نشست‌های جدا امتحان کن. دانش‌آموز پیش از دبیر هیچ چت، تخته یا دسترسی رسانه‌ای نداشته باشد. دبیر زنگ امروز را شروع کند؛ ورود دانش‌آموز خودکار باشد.
2. با نوبت معتبر، نخستین گوینده دانش‌آموز باشد و میکروفون دبیر روشن نشود. «قطع تصویر» صدای دانش‌آموز را نبندد؛ سپس «قطع میکروفون» فقط صدای همان شخص را ببندد. گرفتن نوبت از همه و ورودِ دوباره با حالت شنونده را هم بررسی کن.
3. یک پیام متنی بفرست، یک تصویر و PDF دوصفحه‌ای باز کن، روی هر صفحه علامت متفاوت بکش و به صفحهٔ نخست برگرد. روی تلفن و تبلت پیمایش و بزرگ‌نمایی و نبود ابزار ویرایش برای دانش‌آموز را ببین.
4. اتصال آخرین دبیر/ناظر را قطع کن. دانش‌آموز باید به انتظار برگردد و زمان وقفه محاسبه نشود. پس از بازگشت ناظر، بازشدن همان زنگ با اتاق و نوبت‌های تازه، و حفظ صفحهٔ تخته تا پایان زنگ را بررسی کن. سپس با پایان زنگ، گزارش دبیر و معاون/مدیر، غایب صفر و گزارش مستقل زنگ دیگر را ببین.
5. اعلان‌ها پیش‌فرض خاموش‌اند. [Cron اعلان](../plugin-manager/README-fa.md#notices) روی هاست مدرسه لازم است؛ بررسی ارسال را در صورت نیاز فقط با ربات/گفت‌وگوی اختصاصی تست انجام بده.

اگر صدا مشکل داشت، فقط نسخه، نوع دستگاه و مرورگر و کد ثابت پیام (برای نمونه `MIC-RTC` یا `AUDIO-PLAYBACK`) را ثبت کن. کنترل گوشی واقعی، سنجش ICE از شبکه‌های مختلف، پایداری، راه‌اندازی مجدد VPS و ظرفیت چند کلاس **مرحلهٔ جدا** هستند.
